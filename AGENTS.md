# Third Crisis: Neon Nights — инструменты локализации

Репозиторий инструментов для перевода **Third Crisis: Neon Nights** (Anduo Games):
дамп Unity-ассетов → POT/PO-хаб → компиляция словаря → рантайм-переводчик C#
(scan-and-replace, BepInEx).

> **18+**: репозиторий содержит тексты игры для взрослых. См. `README.md`.

## Состояние: миграция в процессе (с 2026-11-21)

Репозиторий переехал из папки игры (`<Steam>/…/Third Crisis Neon Nights/NeonTranslator/`,
теперь **DEPRECATED**) в отдельный каталог. Миграция **Python → TS** завершена: **Python в проекте
больше нет** (удалён 2026-11-22, см. `docs/rust-vs-ts.md`).

- **Новый код — только `.mts` или `.rs`.** Никаких новых `.py` и `.ps1`.
- **Стек: TypeScript + Rust, языки равнозначны.** Выбор — по измеримому профиту (`AGENTS.md`,
  раздел «Языки», и `docs/language-audit.md`). Портфолийная цель — показать оба языка там, где
  каждый силён, а не «всё на одном».
- **Скорость важна (решение владельца 2026-11-22): рабочий декодер дампера — Rust.**
  Замер: байтовый уровень **3.0×** быстрее (48 с против 145 с), память **2.7×** меньше
  (483 МБ против 1306 МБ), весь пайплайн **2.1×** (57 с против 119 с). TS-реализация остаётся
  **эталоном-образцом** (`npm run dump:ts`): она работает без Rust-тулчейна и служит оракулом
  для `rust_parity` — две независимые реализации проверяют друг друга на реальной игре.
  Цифры и условия пересмотра — `docs/rust-vs-ts.md`.
- **Оракул вместо компилятора.** Молчаливые потери ловятся паритетом и контрольными суммами,
  а не типами: POT после порта совпал с эталоном (37 663 записи, один `sha256`).
- План, инвентарь и порядок портирования — `docs/migration.md` и `tasks/`.

## Принципы и их порядок

Порядок приоритета при конфликте (решение владельца 2026-11-22):

1. **Кайдзен — первичен.** Улучшение делается в моменте, когда проблема **доказана** и правка
   дешёвая (записать гочу, починить повторяющееся спотыкание).
2. **DRY** — одно знание в одном месте.
3. **KISS** — самое простое решение, покрывающее реальную задачу.
4. **YAGNI** — не строить «на случай, когда понадобится».

**Почему они не противоречат.** KISS/DRY/YAGNI ограничивают **умножение кода на будущее**,
кайдзен добавляет **знание и починку после реального случая**. Конфликт появляется только при
подмене смысла: «упростим, выкинув знание» — это ломает кайдзен; «добавим слой заранее» — ломает
YAGNI. Пока каждый принцип применяется по своему назначению, они уживаются.

**Тест перед любой правкой (задавать по порядку):**

1. Это **повторяющаяся** ошибка/гоча? → кайдзен: строка в `MAP.md`; если правка ≤10 строк + тест —
   делаем сразу.
2. Это **второй** реальный случай? → можно выносить общее (DRY).
3. Это **первый** случай «на будущее»? → не делать; записать задачу в `tasks/` (YAGNI).
4. Остались два равных решения? → берём то, что короче (KISS).

**При равенстве «польза vs чистота» выигрывает польза** — но измеримая: снимает повторное
спотыкание, ловит баг, ускоряет рутину. Эстетика («чтобы было красиво/по-книжному») пользой
не считается.

**AI-first: выигрывает не самый строгий язык, а среда с дешёвой проверкой результата.**
Компилятор проверяет типы и память — дёшево и всегда, но не доказывает, что программа делает
нужное. Для данных и пайплайнов обязателен **оракул**: эталонная реализация, golden-файлы,
паритетный прогон, счётчики строк и контрольные суммы. Формула: «компилятор проверяет типы,
оракул проверяет смысл; для пайплайнов данных нужны оба». Практика 2026-11: молчаливую потерю
трёх уровней игры и 48 ложных ошибок QA не поймал бы ни один компилятор — поймали паритет и подсчёт.

## Память агента (между сессиями)

Паттерн **Memory Bank** в минимальном виде: не шесть файлов, а те, которых реально не хватало.
Полный набор Cline (`projectbrief`, `productContext`, `systemPatterns`, `techContext`,
`activeContext`, `progress`) у нас уже покрыт существующими доками — дублировать нельзя (DRY):

- **Правила и устройство** — этот `AGENTS.md`.
- **Зачем и что это** — `README.md`.
- **Технические решения и инварианты** — `docs/migration.md`.
- **Что делать** — `tasks/` (статусы и таблица в `tasks/README.md`).
- **Что уже сделали** — `docs/progress.md` (журнал, свежее сверху). **Читать в начале сессии.**
- **Гочи инструментов** — `MAP.md` рядом со скиллом.

`docs/progress.md` подключён в `opencode.json` → `instructions`, поэтому грузится автоматически
вместе с `AGENTS.md`.

**Начало сессии:** `AGENTS.md` → первая запись `docs/progress.md` → `tasks/README.md`.
**Конец сессии:** дописать 3–6 строк в `docs/progress.md` (что сделали, где остановились,
что дальше — ссылкой на задачу, не пересказом).

**Внешние системы памяти не используем** (проверено 2026-11-22): Memoir, mem0, OpenMemory и
подобные решают ту же задачу, но добавляют второй VCS, второй источник правды и часто Python.
У нас память — файлы в git: версионируется теми же коммитами, читается глазами, диффится в PR.
Пересматривать только если память перестанет влезать в контекст (сейчас это единицы КБ) —
и тогда только TS-реализацией и в `indie-ops`, не в проектном репозитории.

### Кайдзен

Скилл кайдзена — **общий** (`indie-ops/skills/kaizen`), копию в репозиторий не кладём: правило
«общие тулзы живут в `indie-ops`». А `MAP.md` — наоборот, живут здесь, рядом со скиллами
(знание про этот проект не должно уезжать в общий репозиторий).

```bash
npm run kaizen          # состояние MAP по скиллам (.opencode/skills)
npm run kaizen -- --strict
```

Правило записи: `симптом → причина → проверено (дата) → что делать`. Гипотеза — в `tasks/`,
не в MAP. Дешёвая правка (5–10 строк + тест) — сразу; дорогая — задачей.

## Структура

```text
.opencode/skills/          # самодостаточные скиллы (SKILL.md + scripts + tests)
  pipeline-common/         # общие фильтры пайплайна — единственный владелец
  extract-text/            # POT/PO/DAT: po_file, po2dat, potgen + inventory (TS)
  dump-assets/             # дамп Unity-ассетов (PYTHON-ОСТРОВ: UnityPy)
  build-translator/        # C# рантайм + сборка DLL/прокси
  translate-local/         # пакетный перевод через локальную LLM
  translate-qa/            # офлайн-QA перевода
  translates/              # правила перевода (core + языки)
  deploy-translator/       # деплой в игру
po/                        # template.pot + <lang>.po — ИСТОЧНИК ПРАВДЫ (не форматировать)
fonts/                     # TTF для кириллицы/ CJK
runtime/                   # артефакты сборки (DLL, patch_*.dat) — не трекаются
scripts/                   # общие скрипты репо (поиск игры и пр.)
docs/                      # архитектура, миграция
tasks/                     # очередь задач (протокол — tasks/README.md)
tmp/                       # временное, в git не попадает
```

## Пайплайн

```text
npm run dump (Rust) / dump:ts ─→ tmp/dump/ (JSONL, вне гита)
        │
        ▼
potgen ─→ po/template.pot (источник правды)
        │
        ▼
po/<lang>.po ─→ po2dat ─→ runtime/patch_<lang>.dat (JSON-lines)
        │
        ▼
deploy ─→ <игра>/…/Managed/ (DLL + patch + шрифт + active_lang.txt)
```

Рантайм читает **один** `patch_<lang>.dat` (UTF-8, один JSON-объект на строку).
Переводы живут в памяти (scan-and-replace), бинарники игры не модифицируются.

## POT: что внутри и чего нет (снимок 2026-11-21)

- POT — **33 271** запись из 38 973 строк инвентаря; по контексту: `ui` 30 352,
  `speaker:<Имя>` 2 834, `speaker-name` 85; `rich_text` у 2 490.
- **Пробелы:** ~900 уникальных человекочитаемых строк дампа в POT не попадают
  (2,7 %). Причины: 92 652 объекта `read_failed` (19,4 %; текст только в
  `raw_strings` ≤100), лимит UI-строки 50 символов, эвристика «C#-поле с
  точкой», нечитаемые `summaries.global_strings`. ~500 из них — квесты,
  описания предметов, тултипы, релиз-ноты → `tasks/2026-11-21-pot-coverage-gaps.md`.
- **Шум:** 4 297 записей (12,9 %) — имена ассетов и бинарные фрагменты,
  переводить их не нужно → `tasks/2026-11-21-pot-noise-cleanup.md`.
- **Контекста мало:** `#:` refs не пишутся, поэтому переводчик видит только
  спикера и rich-разметку → `tasks/2026-11-21-pot-context-for-translators.md`.
- Полный разбор, цифры и «что оставляем как есть» — `docs/review-2026-11-21.md`;
  грабли по модулям — `MAP.md` скиллов `extract-text`, `pipeline-common`,
  `dump-assets`.

## Языки: TypeScript и Rust равнозначны, Python запрещён

Решение владельца и куратора (2026-11-22): стек проекта — **TS + Rust**, оба языка
**равнозначны**. Нет «главного» языка: выбор делается по **измеримому профиту**.
**Python запрещён** и не добавляется; остатки помечаются DEPRECATED и удаляются.

Правило выбора (применять к каждому новому/мигрируемому куску):

- **Профит измеряется в процентах, а не в секундах.** 310 мс на маленьком проекте — ничто, но
  те же 10 % на 300 МБ — это десятки секунд в каждом прогоне. Поэтому замер делается в
  **МБ/с и в относительном приросте**, а не «сколько секунд сейчас».
- **Порог предложения миграции — прирост ≥ 10 %** на реальной нагрузке. Это уже основание
  поставить вопрос о переносе. Само решение — после оценки **стоимости переноса** и
  согласования с владельцем: 10 % — порог предложения, не автоматического переезда.
- **Rust**, если верно хотя бы одно:
  - **capability gap** — TS объективно не умеет (нет зрелой библиотеки, нужен доступ к рантайму,
    железу или бинарному формату, которого нет в JS-экосистеме);
  - **измеренный профит ≥ 10 %** на реальной нагрузке (МБ/с, память, старт) **и** путь, который
    выполняется регулярно или растёт вместе с проектом;
  - **ресурсы критичны**: размер бинаря, потребление памяти, время старта (утилита для
    пользователей, GUI, WASM).
- **TS**, если:
  - работа I/O-связана (сеть, LLM, диск, обёртки над компиляторами);
  - объёмы малы и время прогона не критично;
  - важна экосистема (JSON, PO/POT, CLI, сайт, интеграции).
- **Спорный случай** — сначала **замер** (бенчмарк + профиль), потом решение. Без цифры Rust
  не вводится; «на Rust быстрее» — не аргумент.

Обязательный артефакт: решение и обоснование фиксируются в `docs/language-audit.md`
(аудит по компонентам) и в задаче на миграцию. Обратная миграция Rust → TS допустима по тому же
правилу: если профит исчез, код возвращается на TS.

Запреты и границы:

- **Python** — нельзя добавлять, нельзя использовать в новых прогонах.
- **PowerShell** — не развиваем: новые скрипты только `.mts`; старые переносятся задачами.
- **C#** — только там, где его требует Unity-рантайм (плагин), это не «язык проекта».
- **C/C++** — не вводим: если нужен нативный код, это Rust.

## Рамки мода

- **Только текст.** Озвучка (TTS, клоны голоса, VoxCPM и любое аудио) не входит в проект
  и не планируется.
- Несколько языков одновременно; выбор языка — **наша собственная панель в игре**
  (штатный селектор разработчики скрыли: в `StreamingAssets/Languages/` пусто).
- Оригинал не модифицируется: перевод подменяется в памяти (scan-and-replace).

## Языки

Единый источник — `config/language-priority.json` (копия приоритета TSSR: языковая статистика
Steam, окт. 2026). Правила:

- Язык-источник — `en`: его текст в `po/template.pot`, отдельного `en.po` нет.
- Остальные языки — `po/<code>.po`; **порядок везде берётся из конфига**, руками не переставлять.
- Новый язык = строка в JSON + `po/<code>.po` + запись в списке UI.
- Страж: `node scripts/languages.mts --check` и `scripts/languages.test.mts` — набор языков и
  порядок обязаны совпадать с конфигом.

Хардкода путей нет: без env путь ищется по Steam-библиотекам.

## Соглашения

- **Коммит — только по явной просьбе человека.** Ни авто-коммитов, ни «промежуточных».
  С 2026-11-22: **владелец коммитит сам после ревью** — агент не коммитит и не пушит даже
  при зелёных тестах; показывает diff/список файлов и ждёт решения.
- Проверяй сохранённый `.mts` сразу: `npx oxlint --fix <файл>` + `npx prettier --write <файл>`,
  сомнения в типах — `npm run typecheck`.
- Тесты — `node --test` рядом с кодом (`*.test.mts`), не pytest (pytest остался только у
  python-острова и C#-сборки).
- **Данные не форматируем:** `po/`, `fonts/`, `runtime/` под prettier не попадают (`.prettierignore`).
- **Запись файлов — атомарная** (`.part` → rename): обрыв посреди записи не должен обнулять
  каталог переводов.
- **JSON — только для конфигов.** Bulk-данные (дампы, каталоги) — JSONL.
- **Длина не критерий качества перевода.** Никаких проверок «msgstr короче/длиннее msgid».
  Единственная сверка — смысловая.
- Временное — только в `tmp/` этого репо, не в системный `%TEMP%`.
- Доки правятся вместе с кодом, а не после.

## Рантайм (C#), коротко

`NeonTranslatorRuntime.dll` — BepInEx-плагин: перехватывает отрисовку и подменяет текст в памяти.
Кириллица добавляется в TMP-атлас в рантайме (`TryAddCharacters`), CJK для ja/zh/ko рисуется
оверлеем UGUI. Штатного переключателя языка в игре нет — свой оверлей (`F9`).
Подробности — `AGENTS.md` старого репозитория (архив) и `docs/`.
