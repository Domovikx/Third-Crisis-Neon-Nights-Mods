# Шрифты мода — политика и цифры

Решение владельца (2026-11-25): литературные шрифты TSSR (Literata) **не переносим** — это
другая игра и другой жанр. Основной шрифт латиницы/кириллицы — **игровой Roboto Condensed**
(менять на промежуточном этапе не нужно), CJK — **Noto Sans SC/JP/KR** сабсетами по символам
корпуса, цепочка фолбэков `Roboto Condensed → Noto (CJK)`. У каждого шрифта рядом лежит файл
лицензии.

## Кто где используется

- **Латиница и кириллица (ru/de/es/fr/it/pl/pt, интерфейс, имена, диалоги)** —
  `fonts/RobotoCondensed-Regular.ttf`. Это шрифт самой игры: метрики и рисунок совпадают с
  оригинальным UI, поэтому перевод не «выглядит вставкой». Файл **не меняем** (не инстансим,
  не сабсетим): в нём уже есть кириллица (169 из 175 символов русского корпуса, остальное —
  глитч-штрихи и полноширинные скобки, их закрывает CJK-фолбэк).
- **Китайский** — `fonts/NotoSansSC.ttf`, **японский** — `fonts/NotoSansJP.ttf`,
  **корейский** — `fonts/NotoSansKR.ttf`: региональные формы иероглифов (в ja нельзя
  подставлять SC-начертания — другие варианты знаков).
- **`fonts/NotoSansMarks.ttf`** — 5 комбинируемых штрихов `U+0334..U+0338` (плюс NBSP/SHY).
  В корпусе есть «глитч»-строка `I̵ ̵w̸o̴n̶'̶t̶ …`; ни Roboto Condensed, ни Noto CJK этих
  знаков не содержат, без отдельного мини-шрифта строка превращается в квадраты.
- **Акцентный/заголовочный шрифт (Orbitron и подобные) — не поставляем.** Игра рисует логотип
  картинкой; отдельного «техно»-шрифта в её ассетах нет. Если меню позже потребует display-шрифт,
  берём OFL-шрифт (Orbitron — OFL 1.1), кладём сабсет и `fonts/LICENSE-OFL-Orbitron.txt`;
  до этого — YAGNI.

## Цепочка фолбэков

Порядок = приоритет: первым идёт шрифт, рисующий язык, дальше — те, что закрывают дыры.

- **latin** (ru/de/es/fr/it/pl/pt): игра → `lat` (Roboto Condensed) → `SC` → `JP` → `KR` → `marks`
- **zh**: игра → `SC` → `lat` → `JP` → `KR` → `marks`
- **ja**: игра → `JP` → `SC` → `lat` → `KR` → `marks`
- **ko**: игра → `KR` → `SC` → `lat` → `JP` → `marks`

Почему SC есть даже в латинской цепочке: в переводах на европейские языки встречаются
одиночные иероглифы и полноширинные скобки `（）` (см. «Дефекты корпуса»), их должен чем-то
нарисовать фолбэк.

## `preload = True` и прирост глифов

В логе рантайма статический атлас игры — **236** глифов (только ASCII). Наше динамическое
лицо начинается с нуля, поэтому его строка выглядит как `chars 0 -> N`, а «прирост поверх игры»
считается как 236 + N. N — число не-ASCII символов языка:

- ru 83 (итого 319), de 30 (266), es 26 (262), fr 60 (296), it 30 (266), pl 60 (296),
  pt 35 (271), zh 2 410 (2 646), ja 1 684 (1 920), ko 1 156 (1 392)

Чтобы строка печатала `= True`, прогревать нужно **все** лица цепочки, а не одно: 5 штрихов
есть только у `marks`, одиночные китайские знаки в ja/ko — только у `SC`. Честный критерий:

```text
needed        = уникальные не-ASCII символы переводов языка
по каждому лицу цепочки: добавить needed ∩ cmap(лицо), напечатать before→after
unrenderable  = needed \ объединение cmap(цепи)
preload       = True ⟺ unrenderable пусто
```

Формула «`added == list.Count` на одном лице» даст `False` на любом языке, где встречается
глитч-строка или чужой иероглиф, хотя визуально всё нарисуется фолбэком.

## Атлас: сколько нужно текстур

Динамический SDF-атлас 2048×2048 (Alpha8 = 4 МБ VRAM). Ёмкость ≈ `(2048/(point+2·padding))²`:

- point 90, padding 9 (текущие дефолты) — 324 глифа/атлас: zh 2 410 → **8 атласов (~32 МБ)**
- point 64, padding 5 — 729 глифов: zh → **4 атласа (~16 МБ)**
- point 48, padding 5 — 1 225 глифов: zh → **2 атласа (~8 МБ)**
- point 40, padding 4 — 1 764 глифа: zh → **2 атласа (~8 МБ)**

Для текста меню/диалогов на 20–40 px достаточно point 48–64: SDF в 2× от экранного кегля
остаётся резким, а VRAM и время прогрева падают вдвое-втрое. Меньше 40 не брать — на крупных
заголовках поплывут края.

## Ширина строк и «вылезание»

Кегль TMP нормирует через unitsPerEm, так что поднимать размер для CJK не нужно — а вот
**ширина** отличается: средний знак корпуса занимает (по hmtx наших шрифтов) **0.561 em** для
русского, **1.000 em** для китайского, **0.999** для японского, **0.918** для корейского.
То есть строка той же длины в переводе на zh шире английской примерно в **1.8–2 раза** —
подписи кнопок без авто-подгонки гарантированно вылезут. Вывод для реализации: TMP auto-size
(или ступенчатое уменьшение кегля с полом 60 % от исходного) обязателен для всех кнопок и
панелей; смысл текста не обрезать. Если на ревью CJK покажется «мельче» — точечно +1 px на
язык, без глобального правила.

## Дефекты корпуса, которые видны как «квадраты» (не шрифт)

Это не дыры шрифтов, а строки, которые стоит поправить в `po/`:

- `I̵ ̵w̸o̴n̶'̶t̶ ̵l̸e̶t̸ ̶y̷o̴u̶.̴` — 5 комбинируемых штрихов; в переводах сохранены. Пока
  поставляем `NotoSansMarks.ttf`, но проще один раз перевести строку без них.
- `（）` (U+FF08/FF09) в ru/de/es/fr/it/pl — полноширинные скобки в европейском тексте.
- Китайские знаки в не-китайских переводах: `中器文机翻译` (de/pl/ru), `秃鹫` + `译` (ja),
  `简` + `译` (ko) — следы машинного перевода, правильный японский/корейский вариант другой.

## Пересборка сабсетов (одноразово, артефакты в git)

Исходники: `fonts/NotoSansSC.ttf` и `fonts/NotoSansJP.ttf` — variable-версии Google Fonts;
KR — `google/fonts/ofl/notosanskr/NotoSansKR[wght].ttf`; marks — `ofl/notosans/NotoSans[wdth,wght].ttf`.
Набор символов — msgstr из `po/<lang>.po` (SC — объединение всех языков, чтобы работать
глобальным фолбэком), плюс ASCII и `NBSP/SHY`.

```bash
# 1) инстанс Regular (иначе останется Thin) + 2) сабсет по набору символов
fonttools varLib.instancer NotoSansKR[wght].ttf wght=400 -o NotoSansKR-Regular.ttf
pyftsubset NotoSansKR-Regular.ttf --unicodes-file=chars.txt --layout-features='*' \
  --name-IDs='*' --output-file=fonts/NotoSansKR.ttf
```

Скрипт-генератор — разовый, в репозитории не живёт (Python в проекте запрещён): в git лежат
готовые `.ttf`, а проверка покрытия — `scripts/font_coverage.mts` (чистый TS, читает cmap сам).

## Чек-лист интеграции (что должно быть в коде)

- Раскладка установки: `<игра>/mods/NeonTranslatorDX/fonts/` (рядом с DLL;
  рантайм читает `Path.Combine(Assembly.Location, "fonts", ...)`), вне папки —
  только лоадер `dwmapi.dll`.
- `NeonFonts.GetFace("ko")` → `fonts/NotoSansKR.ttf` (в установке —
  `<игра>/mods/NeonTranslatorDX/fonts/`); **не** `%WINDIR%\Fonts\malgun.ttf`
  (чужая система, другой рисунок, у части игроков файла нет).
- `AttachFallbacks` — порядок из «Цепочки» выше; `marks` добавляется последним.
- `Warmup` — критерий `preload = True` по объединению cmap цепочки, а не по одному лицу.
- `deploy.mts` → `CJK_FONTS = [SC, JP, KR, Marks]` (уже).
- `package_release.mts` → `fontEntries(lang)`: Roboto+SC всегда, JP для ja, KR для ko,
  Marks для латинских языков (уже); тексты релиза/README — обновить список файлов.
- `fonts/LICENSE-*.txt` едут вместе со шрифтами в архиве (лицензия обязана быть рядом).

## Рантайм: клон игрового ассета (2026-11-25)

Итог измерения в живой игре (`UiProbe` в логе): у игровых TMP-ассетов **есть**
`m_SourceFontFile`, и `FontEngine.LoadFontFace(Font)` для них возвращает `Success`
(в отличие от шрифтов, созданных через `CreateDynamicFontFromOSFont`, — там
`Invalid_File`, из-за этого старый код и получал `preload ... = False chars 236->236`).
Поэтому кириллица теперь рисуется **клоном игрового ассета**:

- `Instantiate(gameFontAsset)`, у клона: `atlasPopulationMode = Dynamic`,
  атлас 2048², `isMultiAtlasTexturesEnabled = true`, атлас[0] — приватная копия
  запечённых глифов игры (ASCII остаётся пиксель-в-пиксель), атлас[1] — новый
  под кириллицу;
- источник — **TTF игры** (тот же `m_SourceFontFile`), padding/renderMode/материал
  копируются у игрового ассета, материал клонируется (иначе менялся бы сам ассет игры);
- `TryAddCharacters` растит клон штатным путём TMP (мульти-атлас), затем клон
  ставится первым в fallback-цепочку: клон → SC → JP → KR → marks (+ наше лицо
  DX-lat последним);
- если у игрового лица нет нужного глифа в TTF (Orbitron-Black: `Ж` = 0), клон
  не поможет — тогда первым фолбэком ставится клон игрового
  `Roboto-Condensed_DialogueUI` (TTF игры, point 95, padding 9, материал игры).

Лог (ru): `Fonts: cloned 'Roboto-Condensed_DialogueUI' -> 'DXclone-...' source='Roboto-Condensed'
point=95 padding=9 material='Roboto-Condensed Atlas Material (DX clone)'`,
`Fonts: fallback front font='DXclone-...' ... on 'Orbitron-Black SDF'`,
`Font: preload chain ru = True: needed 72 (83 non-ASCII in corpus, 11 already baked),
covered 72, unrenderable 0 | game 236 + dynamic 83 -> 319 glyphs`,
`RenderProof: 'П' U+041F asset='DXclone-Roboto-Condensed_DialogueUI'`.

Атлас под CJK: point 64 / padding 5 (было point 89/90, padding 9) — zh 2 409
не-ASCII глифов укладываются в 4 текстуры 2048² (16 МБ VRAM) вместо 8 (32 МБ);
время прогрева цепочки ~1.1–1.3 с на старте.

Сабсеты SC/JP расширены (2026-11-25): к корпусу добавлены полные диапазоны
`U+3000..303F` (CJK-пунктуация), `U+3040..30FF` (хирагана/катакана) и
`U+FF00..FF65` (полноширинные формы) — иначе страница-образец показывала тофу на
редких канах и `；`. Размеры: SC 1 187 640 → 1 228 856 Б (3 692 глифа),
JP 730 344 → 1 080 564 Б (3 056). `npm run fonts:check` — 0 непокрытых.

Скрытые страницы (только для отладки, в обычном UI не видны):
`Ctrl+F12` — «Font specimen» (все наборы, счётчики `tofu`, красная подсветка дыр;
открывается и файлом `fontdebug.txt` рядом с DLL), вкладка Compare — кандидаты
шрифтов (Roboto Condensed / Roboto / Inter / Noto Sans / IBM Plex Sans / Source Sans 3,
файлы и OFL/Apache-лицензии в `fonts/`), кнопка «Применить» меняет латинское лицо
