# Контракт `po/template.pot`

`po/template.pot` — корень текстового пайплайна:

```text
дамп JSONL → template.pot → po/<lang>.po → runtime/patch_<lang>.dat → игра
```

POT — единственный источник английских строк. Ошибка в нём множится на все
10 языков сразу: пропущенная строка не появится ни в одном переводе, неверный
ключ не соединится ни с одним, испорченная разметка ломает рендер везде.
Поэтому контракт зафиксирован здесь, а проверки — `scripts/pot_invariants.mts`
(функция `checkPot(potPath, opts?) → Violation[]`).

## Как проверять

```bash
# Структура и формат (дамп не нужен; работает в CI всегда)
node scripts/pot_invariants.mts po/template.pot

# Полный контракт: сверка с дампом (полнота, выдуманное, rich, счётчики)
node scripts/pot_invariants.mts po/template.pot --dump tmp/dump-new

# Плюс паритет с Rust-сборкой (инвариант 12)
rust-l10n potgen --root . --dump tmp/dump-new --out tmp/pot-rust.pot --created "2000-01-01 00:00+0000"
node scripts/pot_invariants.mts po/template.pot --parity tmp/pot-rust.pot

# Машинный вывод и строгий режим (падать и на предупреждениях)
node scripts/pot_invariants.mts po/template.pot --dump tmp/dump-new --json --strict
```

Код выхода: `0` — ошибок нет, `1` — есть нарушения `error` (или любое при
`--strict`), `2` — ошибка запуска (нет файла/дампа, плохие аргументы).

В коде:

```ts
import { checkPot, summarizePot } from "./scripts/pot_invariants.mts";

const violations = await checkPot("po/template.pot", { dumpPath: "tmp/dump-new" });
// [] = нарушений нет; иначе [{ invariant, code, severity, where, detail }, …]
```

У нарушения есть `severity`:

- `error` — POT испорчен, это ударит по всем языкам;
- `warn` — дефект генерации/статистики: POT сегодня корректен, но контракт
  нарушен (или строка данных потеряна молча).

`limit` в `opts` (по умолчанию 20) ограничивает число нарушений одного кода;
скрытые считаются и дописываются в `detail` («+ещё N»).

## Инварианты

### 1. Детерминизм

- **Что гарантирует:** один и тот же дамп даёт один и тот же POT (кроме
  `POT-Creation-Date`), независимо от порядка обхода файлов/объектов.
- **Зачем:** иначе `git diff` шатается от прогона к прогону, а переводчики
  видят «новые» строки, которых нет.
- **Как проверяется:** с `--dump` POT строится в двух порядках (прямой и
  обратный) и сравнивается. Расхождение = предупреждение `order-dependent`
  с числом затронутых записей.
- **Если нарушить:** шумовые диффы на десятки тысяч строк, потерянная история
  переводов при `po_update` (строки «исчезают и появляются»).
- **Известное состояние:** 2 записи зависят от порядка по `rich_text` (конфликт
  вариантов у одного ключа) и 1 172 — по `src` (`dialog` vs `bundle`/`raw`:
  метка — первого вхождения). Правило «первое вхождение побеждает»; для
  политики это значит, что классы `dialog`/`bundle` частично перекрываются.
  См. «Найденные дефекты» и `docs/pot-provenance.md`.

### 2. Идемпотентность

- **Что гарантирует:** `potgen --update` на неизменном дампе не меняет файл.
- **Зачем:** повторный прогон пайплайна не должен трогать `po/*.po`.
- **Как проверяется:** с `--dump` файл сравнивается с перегенерацией (дата
  нормализуется). Расхождение = `stale` с числом ключей «нет в файле» и
  «лишних».
- **Если нарушить:** POT и дамп расходятся; `po_update` переносит переводы в
  устаревший каталог, часть строк теряется.

### 3. Полнота

- **Что гарантирует:** каждая переводимая строка дампа присутствует в POT
  (с учётом правил: пустые строки отброшены, ui-двойники удалены).
- **Зачем:** пропущенная строка не появится ни в одном языке. Это дефект,
  который в игре выглядит как «непереведённая строка навсегда».
- **Как проверяется:** инвентарь дампа (тот же `scanDump`) даёт ключи
  `(text, msgctxt)`; каждый ключ, которого нет в POT и который не является
  ui-двойником, = `missing-entry` с источником (`kind/source: text`).
- **Если нарушить:** строка молча исчезает из всех языков (класс
  `pot-coverage-gaps`, но уже как регрессия, а не известный пробел).

### 4. Отсутствие выдуманного

- **Что гарантирует:** обратное включение — каждый ключ POT выводится из дампа.
- **Зачем:** выдуманный/устаревший `msgid` не встретится в игре никогда;
  переводчик тратит время на строку, которой нет, а `po2dat` раздувает `.dat`.
- **Как проверяется:** ключи POT сравниваются с ключами инвентаря; лишние =
  `invented-entry` (адрес: строка POT, `msgid`/`msgctxt`).
- **Если нарушить:** «мёртвые» переводы, ложное чувство покрытия, раздутый
  рантайм-словарь.

### 5. Уникальность

- **Что гарантирует:** нет двух записей с одинаковым `(msgid, msgctxt)`.
- **Зачем:** дубль = двойной перевод одного текста и неоднозначность в
  `po2dat` (побеждает первый по порядку файла).
- **Как проверяется:** структурный проход по POT; повтор пары =
  `duplicate-key` с номерами обеих строк.
- **Если нарушить:** перевод расходится по двум записям, в игре побеждает
  случайная (порядок файла), в `.dat` — `DUPE`.

### 6. Порядок

- **Что гарантирует:** записи отсортированы по `(msgid, msgctxt)` в порядке
  code points (как Python `str`), а не UTF-16.
- **Зачем:** стабильные диффы и предсказуемый «earliest wins» в `.dat`.
- **Как проверяется:** сравнение соседних записей; инверсия = `unsorted`.
  Независимость от порядка ФС проверяет инвариант 1.
- **Если нарушить:** каждый прогон переставляет записи, ревью переводов
  невозможно, история git превращается в кашу.

### 7. Rich-разметка (`#. rich_text`)

- **Что гарантирует:** если в источнике есть TMP-разметка, она записана
  целиком; `<font>`/`<material>` вырезаны; значение не обрезано и не
  переэкранировано; `rich_text` не дублирует `msgid`.
- **Зачем:** рантайм выбирает `rich_translation` > `translation` > `rich_text`
  > `text`. Потеря разметки = потеря цвета/курсива в игре; лишние
  > `<font>`/`<material>` = неверный шрифт (выбор за рендерером).
- **Как проверяется:**
  - без дампа: `rich-empty`, `rich-font-tag`, `rich-equals-msgid`,
    `rich-duplicate`, `rich-syntax`, `rich-fragment` (ключ не совпадает с
    полным текстом — обрывок `text`, см. `docs/pot-skip.md`);
  - с `--dump`: значение сравнивается побайтово с источником —
    `rich-missing` (разметка есть, комментария нет), `rich-mismatch`
    (обрезано/изменено/переэкранировано), `rich-extra` (комментарий без
    источника).
- **Если нарушить:** цветные реплики теряют цвет во всех языках; или
  появляется шрифт, которого нет (тофу/битые глифы).

### 8. Экранирование и round-trip

- **Что гарантирует:** `parse(POT)` восстанавливает ровно исходные строки:
  кавычки, `\n`, `\t`, `\\`, не-ASCII; файл — канонический вывод генератора
  (однострочные поля, один завершающий `\n`, без `#:`/`#,`/`# ` в записях).
- **Зачем:** битый эскейп ломает не одну строку, а разбор всего файла:
  следующие записи съезжают, `po_update` теряет переводы.
- **Как проверяется:** синтаксис (`syntax`), каноничность каждого поля
  (`poEscape(parse(raw)) === raw` → `escape-noncanonical`), запрет
  многострочных полей в записях (`field-multiline`), запрет refs/flags/
  переводческих комментариев (`refs`, `flags`, `translator`) и полная
  проверка `parse → render == файл` (`roundtrip`).
- **Если нарушить:** одна «сломанная» кавычка превращает остаток файла в
  мусор; переводы соседних строк уезжают (класс SHIFT).

### 9. Триаж и счётчики

- **Что гарантирует:** каждая отброшенная строка имеет причину (пустая,
  дубль, ui-двойник), а счётчики прогона сходятся с фактическим POT.
- **Зачем:** «потерялось 500 строк» должно быть арифметикой, а не сюрпризом;
  счётчики читают люди и агенты, чтобы решать, всё ли в порядке.
- **Как проверяется:** с `--dump` — число записей POT против каталога
  (`entry-count`), просочившиеся ui-двойники (`ui-twin-leaked`), счётчики
  `mergedTwins`/`rich` против факта (`merged-twins-counter`, `rich-counter`),
  арифметика дублей (`duplicate-accounting`), шум в POT (`noise-entries`,
  предупреждение с числом).
- **Если нарушить:** POT теряет строки без объяснения, а отчёты генератора
  врут — решения принимаются по неверным числам.

### 10. Кодировка

- **Что гарантирует:** UTF-8 без BOM, только LF, нет NUL и невидимых
  символов, которых не было в источнике (ZWSP, ZWNJ/ZWJ, BOM, soft hyphen,
  bidi-контролы, U+2028/2029, U+FFFD, управляющие).
- **Зачем:** BOM/CRLF ломают байтовый паритет и диффы; невидимки
  не отображаются, но ломают поиск рантайма (строка «не находится» в игре) и
  сравнение переводов.
- **Как проверяется:** BOM (`bom`), CR/CRLF (`crlf`), контрольные символы в
  полях и комментариях (`invisible`). С `--dump` символ, который есть в
  источнике, не считается дефектом генерации.
- **Если нарушить:** рантайм не находит строку (невидимый символ),
  `.dat` и POT разъезжаются по байтам, QA сравнивает не то.

### 11. Заголовок и шаблонность

- **Что гарантирует:** первый блок — `msgid ""`, в шапке есть обязательные
  поля, `Content-Type: text/plain; charset=UTF-8`,
  `Content-Transfer-Encoding: 8bit`, корректная календарная дата
  `YYYY-MM-DD HH:MM+0000`, и это шаблон: `msgstr` у записей пуст.
- **Зачем:** без `charset=UTF-8` инструменты PO читают файл в другой
  кодировке; непустой `msgstr` в шаблоне — «перевод», который `po_update`
  разнесёт по языкам как исходник.
- **Как проверяется:** `header-not-first`, `header-duplicate`,
  `header-has-msgctxt`, `header-no-msgstr`, `header-field-missing`,
  `header-charset`, `header-encoding`, `header-date-missing`/
  `header-date-invalid`, `template-msgstr-filled`.
- **Если нарушить:** массовое искажение текста в редакторах PO (кодировка),
  либо английский «перевод» протекает во все языки.

### 12. Паритет генератора с золотом (Rust → слепок)

- **Что гарантирует:** `tools/rust-l10n potgen` даёт побайтово тот же POT, что
  замороженное золото — `test_data/pot-golden-small.pot` и паспорт
  `test_data/pot-golden.json` (`sha256` полного `po/template.pot`, число записей).
- **Зачем:** второй реализации больше нет — TS-эталон (`potgen.mts`) удалён
  2026-11-24; слепок, снятый с него до удаления, и есть оракул. Если Rust
  разошёлся с золотом, «правильный» POT неизвестен, и ошибка уйдёт в релиз.
- **Как проверяется:** **не дублируется** — за паритет отвечает
  `scripts/text_parity.test.mts` (мини-дамп в `npm test`, реальный дамп —
  когда есть сборка и дамп). Для разового прогона `checkPot` принимает
  `--parity <pot>` / `parityPot` и сравнивает файлы побайтово (кроме
  `POT-Creation-Date`); расхождение = `parity-diff`.
- **Если нарушить:** языки собираются из POT, которого никто не проверял;
  различия всплывают только в игре.

### 13. Устойчивость к битому дампу

- **Что гарантирует:** обрезанная/битая JSONL-строка не роняет генерацию и
  не порождает записей. Такие строки учитываются и показываются.
- **Зачем:** дамп — результат работы внешнего декодера; падение на одной
  строке из 578 000 останавливает весь пайплайн, а «тихий» пропуск теряет
  текст без следа.
- **Как проверяется:** с `--dump` дамп перечитывается и считаются строки,
  которые `JSON.parse`/проверка «объект» отбрасывают. Ненулевое число =
  `dump-ignored-lines` (предупреждение, с примерами). Фантомные записи
  ловятся инвариантом 4, падение — тестом `pot_contract.test.mts`.
- **Если нарушить:** либо генератор падает на середине, либо POT «худеет»
  без объяснения (класс «молчаливая потеря данных»).

### 14. Провенанс (`#. src:`)

- **Что гарантирует:** у каждой записи POT есть метка источника из
  фиксированного списка (`dialog`, `bundle`, `settings`, `us`, `global`,
  `field:<ИмяПоля>`, `raw:<TypeName>`), а при сверке с дампом она равна
  метке генератора.
- **Зачем:** отбор «текст или мусор» по внешнему виду доказал
  несостоятельность (фильтр `dot+upper` резал прозу и пропускал мусор).
  Происхождение строки машина знает точно, поэтому политика отбора
  принимается по `src`, а не по виду (`docs/pot-provenance.md`).
- **Как проверяется:** формат `#. src: …`, метка из списка
  (`src-missing`/`src-syntax`/`src-unknown`/`src-duplicate`); с `--dump` —
  равенство метки в POT и в каталоге генератора (`src-mismatch`).
- **Если нарушить:** отчёт по провенансу и будущая политика отбора
  начинают врать; неизвестная метка = сортировка мусора в «нужный» класс.
- **Переходное состояние:** `po/template.pot` на 2026-11-22 сгенерирован ДО
  провенанса, поэтому `npm run pot:check` даёт `src-missing` на каждой записи
  (40 256) — ожидаемо, файл перегенерируется на шаге политики. Для нового POT
  проверка включается сама:
  `node scripts/pot_invariants.mts tmp/pot-labels.pot --dump tmp/dump-after`.
  В коде для старого файла проверка отключается явно (`requireSrc: false`) —
  это единственное место, где контракт временно ослаблен, и оно покрыто
  комментарием.

### 15. Skip-теги (`#, skip` + `#. skip: <id>`)

- **Что гарантирует:** запись, которой перевод не нужен, помечена ПАРОЙ
  «флаг + причина»: `#, skip` и `#. skip: <id правила>`, где id существует в
  `config/pot-skip-policy.mts` (JSON рядом — артефакт); правило подтверждается самой записью (метка
  `src` и условие `when`). Запись при этом остаётся в POT.
- **Зачем:** такие строки не попадают в `po/*.po` и не тратят ни ревью, ни
  GPU — но и не исчезают из шаблона: решение видно и обратимо
  (`docs/pot-skip.md`).
- **Как проверяется:** `skip-no-rule` (флаг без причины), `skip-no-flag`
  (причина без флага), `skip-duplicate`, `skip-syntax`,
  `skip-unknown-rule` (id вне политики), `skip-without-policy` (метка без
  файла политики), `skip-stale` (warn: правило не подтверждается записью).
  Флаг не-`skip` по-прежнему ошибка инварианта 8 (`flags`).
- **Если нарушить:** PO начнёт заводить пустые строки для мусора (или,
  наоборот, терять переводы) — при том что в POT написано «переводить».

## Тон диктора (`#. emotion:`)

- **Что это:** инструкция диктору — КАК произносится строка (состояние
  говорящего/рассказчика), а не что в ней сказано. Всегда по-английски, 2–6
  слов, с заглавной; пример: `#. emotion: Quietly observing, a little flustered`.
- **Единственный холд — POT.** Тон стоит сразу после `#. src:`/`#. skip:` и до
  `#. rich_text:`. В `po/*.po` он НЕ переносится: `po_update` отфильтровывает
  `emotion:` (иначе 6 041 тон размножился бы на 10 языков).
- **Оверлей — данные, а не код** (как `--skip-ids`): разметчик пишет JSON
  `{msgid: "тон"}`, Rust применяет его детерминированно.

  ```bash
  # разметка (LLM снаружи; черновик в tmp)
  node .opencode/skills/extract-text/scripts/emotion_tag.mts --sample 100 \
    --out tmp/emotions_ru.json

  # сборка POT с тоном (без флага — discovery config/emotions.json)
  node scripts/text_cli.mts potgen --dump tmp/dump --out tmp/pot-with-tones.pot \
    --emotions tmp/emotions_ru.json

  # выключить тон (POT как до оверлея)
  node scripts/text_cli.mts potgen --dump tmp/dump --out tmp/pot-plain.pot --no-emotions
  ```

- **Кому ставится:** только озвучиваемым записям — `src: dialog`, не
  `speaker-name`, без `#, skip`. Ключ оверлея — точный `msgid` (дублей в наборе
  озвучки нет); ключи вне POT и неозвучиваемые записи считаются в отчёте
  (`applied/skipped/unused`) и печатаются предупреждением.
- **Пустой оверлей ничего не меняет:** POT байт-в-байт равен сборке без флага
  (проверено на реальном дампе, sha256 совпал).
- **Ещё не сделано (следующий шаг):** инвариант 16 в `pot_invariants.mts`
  (`emotion-syntax`, `emotion-duplicate`, `emotion-on-skip`,
  `emotion-on-non-dialog`), аудит формата/однородности и `config/emotions.json`
  как закоммиченный артефакт — см. `tasks/2026-11-26-pot-voicing-plan.md` (4.3).

## Что проверки не покрывают

- **Смысл перевода** (`po/*.po`) — это QA перевода, а не POT.
- **Покрытие**: какие человекочитаемые строки дампа вообще не попали в
  инвентарь (фильтры `isUiString`, `read_failed`, длина > 50) —
  `tasks/2026-11-21-pot-coverage-gaps.md` и `tasks/2026-11-22-pot-coverage-audit.md`.
- **Шум**: имена ассетов и бинарные фрагменты в POT проверяются только
  счётчиком (`noise-entries`), чистка — отдельная задача
  `tasks/2026-11-21-pot-noise-cleanup.md`.
- **Целостность готовых `.dat`/PO** — `tasks/2026-11-22-data-integrity-lint.md`.

## Снимок 2026-11-22 (реальный дамп `tmp/dump-new`)

```text
node scripts/pot_invariants.mts po/template.pot --dump tmp/dump-new
  записей: 40 256 (rich: 2 374)
  контексты: ui 37 704, speaker:* 2 495, speaker-name 57
  ошибок 0; предупреждений 3
```

Предупреждения (дефекты генерации, POT при этом корректен):

- `order-dependent` — 2 записи зависят от порядка элементов дампа
  (конфликт вариантов `rich_text` у одного ключа, «первое вхождение
  побеждает»).
- `rich-counter` — печатается `rich: 2 452`, в POT `rich_text` 2 374:
  счётчик считает и rich-комментарии записей, удалённых как ui-двойники.
- `noise-entries` — 4 860 записей-шума (3 440 имён ассетов, 1 420
  бинарных фрагментов).

Проверено дополнительно:

- `po/template.pot` байт-в-байт совпадает с перегенерацией из `tmp/dump-new`
  (кроме даты) — инварианты 2, 3, 4 зелёные;
- Rust-сборка (`rust-l10n potgen`) даёт тот же POT — инвариант 12 зелёный
  (`--parity`, 0 нарушений);
- `scripts/text_parity.test.mts` проходит (мини-дамп + реальный дамп).

## Предлагаемые npm-скрипты и шаг CI

`scripts/pot_invariants.mts` — общий вход; `package.json` не менялся этим
изменением (вне зоны задачи). Предлагается:

```json
"pot:check": "node scripts/pot_invariants.mts po/template.pot",
"pot:check:full": "node scripts/pot_invariants.mts po/template.pot --dump \"${TCNN_DUMP_DIR:-tmp/dump-new}\""
```

И в `npm run verify` — `npm run pot:check` (структура, дамп не нужен).

Шаг CI (`.github/workflows/ci.yml`, job `ts`, после `npm test`):

```yaml
- name: POT contract (structure)
  run: npm run pot:check

- name: POT contract tests
  run: node --test scripts/pot_invariants.test.mts .opencode/skills/extract-text/tests/pot_contract.test.mts
```

Полный прогон с дампом в CI невозможен (данных игры в git нет) — это локальный
шаг: `npm run pot:check:full` (или `npm run verify:full`, если такой появится).
E2E-тест с реальным дампом в `pot_contract.test.mts` — opt-in: он сам
пропускается, если дампа нет.
