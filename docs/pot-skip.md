# Теги «перевод не нужен» в POT (`#, skip`)

Решение владельца (2026-11-23): строки, которым перевод не нужен, не удаляются
и не фильтруются «по виду» молча — они **остаются в POT** и получают пару
«флаг + причина»:

```po
#. src: raw:Transform
#. skip: short-token
#, skip
msgctxt "ui"
msgid "!AL7"
msgstr ""
```

Такой перевод виден человеку, обратим одной правкой JSON и не тратит ни
ревью, ни GPU: `po_update` не заводит для него пустых строк в `po/*.po`,
`translate_local` не отправляет его в модель, `qa` не считает пустым
диалогом.

## Политика — данные, а не код

`config/pot-skip-policy.json`:

```json
{
  "rules": [
    { "id": "no-letters", "src": "raw:*", "when": "noLetters" },
    {
      "id": "short-token",
      "src": "raw:*",
      "srcExclude": ["raw:MonoBehaviour"],
      "when": "shortToken"
    },
    { "id": "no-word", "src": "raw:*", "when": "noWord" },
    { "id": "identifier", "src": "raw:*", "when": "identifier" },
    { "id": "fragment", "src": "*", "when": "fragment" }
  ]
}
```

- `id` — имя правила (`[a-z0-9-]`), оно и попадает в POT (`#. skip: <id>`);
  повторы id — ошибка.
- `src` — та же грамматика, что у `config/pot-src-policy.json`: точная метка
  или префикс `*` (`raw:Transform`, `raw:*`, `*`). Опечатка (`raw:Fontt`) —
  ошибка, а не «правило не сработало».
- `srcExclude` — метки, которые правило НЕ трогает, даже если они совпали с
  `src` (та же грамматика). Так `short-token` сужен до всего `raw:*`, кроме
  `raw:MonoBehaviour`: именно там лежат настоящие подписи (`ACCESS`,
  `ACHIEVEMENTS`, `SAVEFILENAME`), и терять их нельзя. Опечатка в
  `srcExclude` — тоже ошибка.
- `when` — условие из `pot_skip.mts`: `noLetters`, `shortToken`, `noWord`,
  `identifier`, `fragment`. Неизвестное условие — ошибка.
- `enabled: false` — правило остаётся в файле для ревью, но не действует.
- `_`-поля — комментарии данных (не исполняются).
- Побеждает ПЕРВОЕ подходящее правило в порядке массива.

Выключить всё — `"rules": []`; выключить одно правило — убрать его или
поставить `enabled: false`. Код при этом не меняется.

## Условия

- **`noLetters`** — в ключе нет ни одной буквы (`\p{L}`): только цифры,
  пунктуация, пробелы.
- **`shortToken`** — нет пробелов и не больше 12 символов. Основной фильтр
  бинарного мусора raw-скана (`!AL7`, `""JA-`, `%EA`).
- **`noWord`** — в ключе нет ни одного токена из ≥3 букв (токен — отрезок
  букв/цифр; цифры разрешены, считаются только буквы). Закрывает шум
  **с пробелом**, который не ловит `shortToken`: `w? |b`, `wK Ax`, `j A`.
  Настоящие подписи не трогает — у `ACCESS` и `SAVEFILENAME` есть слово.
  Замер 2026-11-23: на `raw:*` совпадает с 3 138 записями, из них 2 961 —
  токены без пробелов (их уже закрывает `shortToken`), а 177 — шум с пробелом.
- **`identifier`** — программный идентификатор, а не текст: CamelCase из ≥2
  горбов (`AbilityName`, `Cypher_Timer` — нет, это snake), `snake_case` /
  `CONST_CASE` (`DEFAULT_KEY`, `Char_Klaudia`). Признак **структурный**, а не
  «по виду»: слова с заглавной (`Accept`), аббревиатуры (`ACCESS`, `ARRIVAL`)
  и дефисы (`Neon-Trust`) идентификаторами НЕ считаются и остаются
  переводимыми. Замер 2026-11-23: 2 242 записи `raw:*`, которых не закрывают
  предыдущие правила; ни одна из них не встречается в `dialog`/`us`/
  `settings`/`field:`.
- **`fragment`** — ключ это **хвост** `rich_text`: дамп сохранил `text`
  обрезанным, а полный текст — в `rich_text`.

## Ловушка `fragment`: чистка только по списку TMP-тегов

В данных игры `<` и `>` работают **авторскими кавычками**:

```po
#. rich_text: <i>< Like this, hmmm...? I love these nice big tits. Especially when adorable customers like <b>you</b> request them. >
msgid "you request them. >"
```

Регекс «любой `<...>`» (`<[^>]+>`) съедает кусок от `< Like this…` до `>` в
`<b>` и оставляет ровно `you request them. >` — сравнение «совпало», обрывков
«ноль». Поэтому `stripTmpTags` снимает **только известные TMP-теги** из списка
`TMP_TAGS` (`i, b, u, s, size=, color=, alpha=, material=, link=, sprite=,
pos=, align=, cspace=, indent=, line-height=, mspace=, space=, voffset=,
width=, font=, mark=, nobr, noparse, page, br`); всё остальное остаётся
текстом. Список — данные: новый тег добавляется одной строкой в
`pot_skip.mts` и `pot_skip.rs`.

Порог осмысленности: обрывком считается ключ **≥10 символов и ≥2 слов**
(`FRAGMENT_MIN_CHARS`/`FRAGMENT_MIN_WORDS`). Без порога инвариант ловит шесть
шумовых `">"` из шрифтовой разметки (`<< Declination processed. >>`).

Классы (`classifyRich`), их же показывает инвариант:

- `ok` — после чистки тегов и обрезки пробелов текст совпал;
- `suffix` — ключ = хвост полного текста (дефект дампа; rule `fragment`);
- `mismatch` — ключ в полном тексте не найден вовсе (расхождение на символы,
  например `… 7192>` против `… <7192>`); **в skip не идёт** — это настоящая
  строка с битой разметкой, её надо переводить и починить данные;
- `noise` — расхождение есть, но ключ ниже порога (не диагноз).

## Что делает конвейер

- **`potgen`** ставит `#, skip` + `#. skip: <id>` и пишет журнал
  `tmp/pot-skip.jsonl` (`{rule, src, msgid, msgctxt}`) — ничего не теряется
  молча. Флаги: `--skip-policy <path>`, `--no-skip-policy`,
  `--skip-journal <path>`. То же в Rust (`rust-l10n potgen ...`), POT и журнал
  совпадают побайтово.
- **`po_update`** для skip-записей **не создаёт** строк в PO; уже
  существующий перевод сохраняет и держит метку `#, skip`. Если POT перестал
  помечать ключ, метка из PO снимается. Счётчики отчёта: `skipped`
  (не заведено) и `skip_kept` (сохранено).
- **`translate_local`** исключает skip из очереди (счётчик `skipped` в
  итоговом отчёте), модель не зовётся.
- **`qa`** не считает пустой перевод skip-записи дефектом покрытия (наряду с
  `legacy`/`no-translate`).

## Риски и открытые вопросы

- **`short-token` широкий** (29 % POT): в него попадают и настоящие короткие
  подписи без пробела (`ACCESS`, `ACHIEVEMENTS`, `ALWAYS`). Чисто буквенных
  токенов среди попаданий — 4 340, и это место, где решение принимает человек
  (правило подтверждается один раз); при сомнении — `enabled: false` и
  перегенерация.
- **Примеры владельца не покрыты**: `w? |b` и `wK Ax` оба содержат пробел,
  поэтому `shortToken` их не ловит, а `noLetters` — не их случай. Нужно
  отдельное правило («нет словарных слов»?) — решение вне этой задачи.
- **`fragment` намеренно узкий** (только `suffix`): `mismatch` — реальный
  текст с битой разметкой, его нельзя молча выключать из перевода.
- **`no-letters` сейчас пуст** (0 совпадений): оставлен как дешёвая страховка
  на будущие данные; удалить — одна строка JSON.
