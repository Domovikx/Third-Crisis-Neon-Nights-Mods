# Качество перевода: как измеряем и как улучшаем

Перевод `po/<lang>.po` оценивается **двумя независимыми слоями**, потому что они ловят разное.
Смешивать их нельзя: механика даёт факт, модель — подозрение.

## Слой 1. Механика (детерминированно, без модели)

Всё, что можно решить по данным, решается правилом и покрывается тестом.

| Проверка                    | Где                            | Что ловит                                                                                                       |
| --------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `validate`                  | `translate_local.mts`          | дисбаланс тегов, потеря маркера/токенов, номер строки промпта (`2. …`), потеря кавычек и скобок, утечка промпта |
| канон имён                  | `buildGlossary` + вычитка      | `Роузи` рядом с каноническим `Рози`, имя латиницей                                                              |
| клинический регистр         | `scripts/register_lexicon.mts` | «половой акт», «пенис» в диалоге; `weak`-слова (клитор, влагалище) не дефект                                    |
| потеря откровенности        | `scripts/register_lexicon.mts` | EN `cock`, а в RU нет ни одного откровенного соответствия                                                       |
| утечка промпта              | `scripts/leak_guard.mts`       | в `msgstr` стоит промпт переводчика, а не реплика                                                               |
| покрытие `rich_translation` | `scripts/rt_audit.mts`         | есть теги в оригинале, нет разметки в переводе                                                                  |

Порог в `rt:audit --strict` и в `validate` — гейт: строка не записывается, если проверка не прошла.

## Слой 2. Судья на локальной модели (подозрение, не приговор)

`scripts/qa_judge.mts` спрашивает модель **только про грубые ошибки**: чужая строка, перевёрнутый
смысл, потерянный/выдуманный факт, сломанная грамматика, пол не по адресату. Промпт перенесён из
TSSR (v10: recall 61/64, 0 ложных на чистых).

Регистр судье не доверяем. Замер 2026-11-23 на 120 строках: 34 флага `register-soft` и 4
`register-clinical`, из которых верных — единицы (стоны записаны в клинику, наррация — в
«смягчение»). Поэтому регистр — слой 1, а не мнение модели.

Вторая ступень — `verify`: каждое обвинение перепроверяется отдельным запросом с примерами
отказов. На отложенной выборке (8 строк, размечены руками) — 7/8; без неё первая ступень даёт
~30 % точности.

## Цикл улучшения

```bash
# 1. Найти кандидатов: судья + механика, ничего не правит.
node scripts/qa_judge.mts --lang ru --n 300 --url http://127.0.0.1:8081

# 2. Прочитать список (tmp/qa-judge-ru.md, tmp/qa-judge-ru.bad.jsonl) и подтвердить дефекты.

# 3. Переписать ТОЛЬКО подтверждённые строки.
node .opencode/skills/translate-local/scripts/translate_local.mts \
  --lang ru --improve --keys tmp/qa-judge-ru.bad.jsonl --url http://127.0.0.1:8081

# 4. Повторить судью на тех же строках (--keys принимает .jsonl) и сравнить.
```

Повторный пасс нужен потому, что модель находит новые дефекты в уже переписанном тексте, но
каждый пасс дороже предыдущего по времени: 100 строк ≈ 30 с, полный корпус ≈ 1.5 ч.

Судья **дозапускаемый**: вердикты пишутся в `.jsonl` построчно, а при старте уже отсуженные
ключи пропускаются. Это не украшение: за один вечер прогон дважды умирал, когда другая
сессия освобождала GPU, и первый раз потерял 12 300 готовых строк. Теперь перезапуск
продолжает с места.

## Инвариант данных: PO = только ключи POT

`po/<lang>.po` не хранит ничего, чего нет в `po/template.pot`. Если ключ пропал из POT,
перевод при слиянии **выпиливается** (счётчик `orphan_dropped`, список `orphanItems`
поимённо) — а не остаётся «сиротой для рантайма». Раньше так и было (`#, legacy`), и в `ru`
накопилось 597 записей: 128 давно вернулись в POT, 208 — имена ассетов, 262 — старый корпус.
Сирота в PO некому отдавать; если текст реально нужен игре, чинить надо экстрактор, а не PO.

## Чего этот слой не делает

- Не переписывает строку, если не может назвать дефект: «сделать красивее» — не цель.
- Не трогает asset-идентификаторы: их место в skip-политике POT, а не в переводе.
- Не считает длину критерием (правило проекта): единственная сверка — смысловая.
