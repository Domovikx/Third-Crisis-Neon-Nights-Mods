# Аудит целостности данных POT/PO/DAT

Дата снимка: 2026-11-22. Инструмент: `tools/rust-lint` (Rust, только чтение).
Задача и журнал: `tasks/2026-11-22-data-integrity-lint.md`.

## 1. Зачем отдельный аудит

QA (`npm run qa`) отвечает на вопрос «переведено ли и похоже ли на перевод»: покрытие,
пустые диалоги, copy-through, теги в `.dat`, латиница в `ru`. Этот аудит отвечает на другой
вопрос: **целы ли данные как структура** — ключи, экранирование, кодировка, разметка,
якоря, соответствие `.dat` источнику.

Инструмент не зависит от правил QA и ничего не правит. PO-парсер общий с пайплайном
(`tools/rust-l10n-core`), потому что аудит и генератор обязаны одинаково видеть файл;
все проверки — свои.

## 2. Как запускать

```bash
# сборка и проверки
(cd tools/rust-lint && cargo build --release && cargo test && \
  cargo clippy --all-targets -- -D warnings && cargo fmt --check)

# полный прогон по языкам из config/language-priority.json (из корня репозитория)
./tools/rust-lint/target/release/rust-lint --root . --json-dir tmp \
  --report tmp/lint-report.md

# один язык / калибровка на снимке
./tools/rust-lint/target/release/rust-lint --lang ru --root .
./tools/rust-lint/target/release/rust-lint --lang ru \
  --pot tmp/lint-pot-old.pot --po tmp/lint-ru-old.po --no-dat
```

`rust-lint` ниже — это `./tools/rust-lint/target/release/rust-lint`.

Опции:

- `--root <репо>` — где `po/`, `runtime/`, `config/` (по умолчанию `.`);
- `--lang <код>[,<код>]` — языки; без флага берётся порядок `config/language-priority.json`;
- `--pot`, `--po`, `--dat` — подменить файл (для калибровки на старом снимке);
- `--json-dir` — куда писать `lint-pot.json` и `lint-<lang>.json` (по умолчанию `tmp`);
- `--report` / `--no-report` — markdown-сводка;
- `--no-dat` — проверять только POT/PO (например, для старых снимков без `.dat`);
- `--fail-on-error` — код 1, если есть находки уровня `error` (для CI; по умолчанию 0).

Запись JSON и отчёта атомарная (`.part` → rename), как у остальных инструментов.

## 3. Классы дефектов

50 классов, у каждого фиксированный уровень (`error`, `warn`, `info`) и вердикт
(`data`, `pipeline`, `not-defect`). Полное описание — `src/classes.rs`; ниже группы.

Структура и ключи:

- `pot.duplicate-key` (error, pipeline) — одна пара `(msgctxt, msgid)` в POT дважды;
- `po.duplicate-key-diff` (error, data) — дубликат ключа с разными `msgstr`;
- `po.duplicate-key-same` (info, not-defect) — дубликат с тем же переводом;
- `po.empty-msgid` (error, pipeline) — запись без `msgid` в теле файла;
- `po.malformed-field` (error, data) — строка поля не разбирается парсером;
- `po.orphan-text` (warn, pipeline) — перевод текста, которого нет в POT;
- `po.orphan-context` (warn, pipeline) — текст есть, а контекста (спикера) нет;
- `po.missing-key` (error, pipeline) — ключ POT отсутствует в PO;
- `po.copy-through` (warn, data) — `msgstr == msgid` у фразы;
- `po.copy-through-noise` (info, not-defect) — копия у шума/имени/термина;
- `po.key-drift` (warn, pipeline) — ключ отличается пробелами/невидимками.

Экранирование и кодировка:

- `po.escape.double` (warn, data) — литеральные `\n`, `\t`, `\r`, `\"` в значении;
- `po.escape.backslash` (info, data) — прочий обратный слэш в тексте;
- `po.escape.unknown` (warn, data) — `\x` с неизвестной буквой (парсер молча съедает);
- `po.encoding.zero-width` (error, data) — ZWSP/ZWNJ/ZWJ/BOM/bidi/мягкий перенос;
- `po.encoding.nbsp` (warn, data) — NBSP вместо пробела;
- `po.encoding.mixed-alpha` (warn, data) — кириллица и латиница внутри одного слова;
- `po.encoding.mojibake` (error, data) — UTF-8, прочитанный как cp1251/cp866;
- `po.encoding.typographic` (warn, not-defect) — кудрявые кавычки/апострофы в латинице.

Разметка:

- `po.tag.balance` (error, data) — лишнее закрытие тега;
- `po.tag.nesting` (error, data) — закрытие не в том порядке;
- `po.tag.unclosed` (info, not-defect) — тег открыт до конца строки (TMP закроет неявно);
- `po.tag.missing` (warn, data) — тег оригинала потерян;
- `po.tag.extra` (warn, data) — тег добавлен переводчиком.

`<font>` и `<material>` не участвуют ни в балансе, ни в сравнении: их выбирает рантайм.

Смысловые якоря:

- `po.anchor.numbers` (warn, data) — последовательность цифр не совпала;
- `po.anchor.line-ids` (warn, data) — номер вида `132-` изменился;
- `po.anchor.placeholders` (error, data) — `{0}`, `%s`, `[name]` потеряны/переставлены;
- `po.anchor.empty` (info, not-defect) — пустой перевод (норма для непереведённого языка);
- `po.anchor.single-char` (warn, data) — перевод из одного символа;
- `po.anchor.truncated` (info, data) — похоже на обрезку конца фразы.

Словарь `.dat`:

- `dat.missing-file`, `dat.parse-error` (error, pipeline);
- `dat.duplicate-key` (warn, pipeline), `dat.unknown-field` (info, not-defect);
- `dat.not-in-pot` (error, data) — строка не из POT/PO;
- `dat.not-in-po` (error, pipeline) — текст из POT, которого нет в PO;
- `dat.lost-translation` (error, pipeline) — перевод есть в PO, но не в `.dat`;
- `dat.invented`, `dat.mismatch` (error, pipeline) — перевод в `.dat` без источника/не тот;
- `dat.copy-through` (warn, data), `dat.copy-through-noise` (info, not-defect);
- `dat.collapse` (info, not-defect) — разные переводы одного текста схлопнуты в одну строку;
- `dat.rich-lost`, `dat.rich-mismatch` (error, pipeline), `dat.rich-extra` (warn, pipeline);
- `dat.rt-mismatch`, `dat.rt-tags` (warn), `dat.rt-balance` (error), `dat.rt-unclosed` (info);
- `pot.noise` (info, not-defect) — имя ассета или бинарный фрагмент (калибровка).

## 4. Калибровка

### 4.1 Шум POT: 4 297 воспроизведены точно

На снимке 2026-11-21 (`po/template.pot` из `d1cf11b`, 33 271 запись) инструмент даёт:

```text
isAssetName        3 045
isGarbageFragment  1 545
пересечение          293
объединение        4 297
```

Это ровно известное число. На текущем снимке (40 256 записей) — **4 860**:

```text
isAssetName        3 440
isGarbageFragment  1 761
пересечение          341
объединение        4 860   (12,1 %)
```

Расхождение объясняется ростом POT (+6 985 записей после возврата трёх сцен), а не другим
критерием: те же функции на старом файле дают 4 297. Попутно найден и исправлен дефект
порта: TS-регекс `[0-9]+\s?%$` считает легитимным любой процент в конце строки
(«Accessories - 10%»), а первая версия порта требовала, чтобы цифры стояли в начале;
это давало 19 лишних «шумовых» записей.

### 4.2 `<font>`: 48 ложных дисбалансов не флагаются

Снимок 2026-11-21 с явными `rt` (`tmp/patch_ru.before.dat`, 412 строк с `r` и `rt`):

- отличий по именам тегов **с учётом** `<font>`/`<material>` — **48**;
- после исключения — **0**;
- «только-шрифтовых» (ложных) — **48**.

На текущем `.dat` (374 строки `r`+`rt`): с учётом `<font>` — 44 отличия, после исключения —
1 различие. Это не ошибка: один и тот же набор тегов вложен в другом порядке
(`<color><i>…</i></color>` против `<i><color>…</color></i>`); только-шрифтовых — 43.
Исторические 48 — это ровно тот класс, который инструмент обязан не флагать;
проверено на старом артефакте.

### 4.3 Схлопнутые группы: 54 воспроизведены

На снимке 2026-11-21 `po/ru.po` инструмент находит **54** группы, где у одного текста
несколько разных переводов, а в `.dat` попадёт один. Полный список — в
`tmp/lint-report-2026-11-21.md` (раздел «Схлопнутые группы»). На текущем снимке групп
**6** — и это не потеря проверки, а следствие пересборки POT (см. 5.3): 48 групп исчезли
потому, что у текста пропал второй контекст (спикер), а вместе с ним и второй вариант.

### 5.2 Что оказалось не дефектом

- **4 860 шумовых записей POT** (`pot.noise`) — имена ассетов и бинарные фрагменты;

- **4 871 копия у шума/имени/термина** (`po.copy-through-noise`) и 4 867 в `.dat` —

- **316 180 пустых переводов** (`po.anchor.empty`) — непереведённые языки: `es/fr/it/ja/ko/pt/zh`
  имеют по 4 заполненных строки из 40 257; это состояние проекта, а не дефект.
- **195 незакрытых тегов** (`po.tag.unclosed`, 192 в POT) — `<i>` в начале `rich_text`
  без закрытия: TMP закрывает тег в конце строки, это осознанный приём.
- **78 незакрытых тегов в `rt`** — то же самое, унаследовано от шаблона.
- **57 типографских кавычек** в `de` (15) и `pl` (42) — `„…“` стандарт этих языков,
  поиск по оригиналу они не ломают.
- **3 перевода времени** `6:47pm → 18:47` — корректная 24-часовая запись.
- **35 отличий `rt` по тегам** — добавленное выделение, теги сбалансированы; не ошибка
  структуры, но требует выборочной проверки на вёрстку.

### 5.3 Почему появились 1 321 мёртвый перевод и 48 исчезнувших групп

Пересборка `632f2df` («три ранее потерянные сцены») не только добавила 6 985 записей,
но и **убрала часть старых ключей**: дублирующиеся контексты одного текста
(`speaker:Enforcer` + `speaker:Enforcer 1520`, `speaker:Man` + `speaker:Hooligan`) и
строки, которых больше нет в новой версии сцен. `po:update` переносит переводы по
`(msgid, msgctxt)`; для исчезнувших ключей он оставляет записи в PO (orphan), а для
48 групп с двумя вариантами перевода — оставляет только вариант, чей контекст выжил.

Коммит сообщает «0 потерянных переводов», и это верно для активных ключей: ни один
перевод существующего ключа не пропал. Но 1 321 перевод стал мёртвым, а 48 вариантов
потеряли контекст. Это надо чинить в пайплайне (`po:update` должен отчитываться о
выпавших ключах и предлагать перенос/удаление), а не молча оставлять в PO.

  как комментарий/резерв), либо явно отчитаться о потере;

Не дефект:

## 7. Команды для package.json (зона владельца)

`package.json` в этой задаче не менялся. Предлагаемые скрипты:

```json
"rust:lint:build": "cargo build --release --manifest-path tools/rust-lint/Cargo.toml",
"test:rust:lint": "cargo test --manifest-path tools/rust-lint/Cargo.toml",
"lint:data": "cargo run --release --quiet --manifest-path tools/rust-lint/Cargo.toml -- --root . --json-dir tmp --report tmp/lint-report.md"
```

`lint:data` можно добавить в `verify` после `check:langs`: прогон на текущем корпусе
занимает доли секунды и не требует игры. Для CI — отдельный Rust-джоб по образцу
`rust-qa`/`rust-l10n` (fmt, clippy, test) и `--fail-on-error` на снимке с известными
ошибками (после их починки — обычный прогон).

## 8. Воспроизводимость и оговорки

- Основные числа — снимок **git HEAD** (`632f2df`): POT и PO взяты через `git show`,
  `.dat` собран из этих PO тем же `buildDat`, что и пайплайн (TS-эталон), в `tmp/`,
  чтобы аудит не зависел от параллельно идущей правки переводов. Артефакты снимка —

- Живой прогон (`--root .`) на момент аудита даёт те же структурные классы; числа
  `filled`/`lost` могут меняться, пока идёт перевод. Аудит это и должен ловить: `.dat`
  старше PO — `dat.lost-translation`/`dat.mismatch`. На финальном живом прогоне
  расхождений не было (перевод и сборка совпали).
- Эвристики (`truncated`, `mixed-alpha`, `mojibake`, `typographic`, `line-ids`) —
  сигналы, а не приговоры: в отчёте у каждой находки есть адрес и текст, решение
  принимает человек.
- Калибровка на старом снимке: `tmp/lint-pot-old.pot` и `tmp/lint-ru-old.po` — версия
  `d1cf11b`; `.dat` — `tmp/patch_ru.before.dat` (18535 строк). Команды и полные списки:
  `tmp/lint-report-2026-11-21.md`, `tmp/lint-report-old-dat.md`.
- Аудит не оценивает художественное качество перевода и не заменяет судью/ревью.
