# План перевода: качество прежде объёма

Дата: 2026-11-22. Относится к текстовому переводу всех языков проекта.

## Принцип

Пользователь ждёт **качественный** перевод, а не «процент заполнения». Поэтому порядок такой:
одна строка, доведённая до приёмки, ценнее десяти машинных. Покрытие растёт **волнами**,
и каждая волна закрывает язык целиком по стадиям (ниже), а не «всем по чуть-чуть».

## Что считаем качеством (измеримо)

- **Покрытие**: `filled / total` по `po/<lang>.po` (источник — POT, без выдуманных строк).
- **Механика** (гейт «не хуже»): `npm run qa` — 0 ошибок классов `tag-imbalance` (кроме
  исторических `<font>`), `copy-through` для реального текста, `empty-dialogue` в переведённых
  строках.
- **Терминология**: глоссарий языка применён (имена, SFX, устойчивые термины) — проверяется
  выборкой и судьёй.
- **Контекст**: реплика соответствует спикеру и сцене (выборка + ревью).
- **Отсутствие машинных артефактов**: нет обрывов, дублей, служебных пометок, чужих языков.
- **Выборка человека**: N случайных строк на 1 000; порог приёмки — не более X замечаний
  (X фиксируется на пилоте языка).

## Стадии для каждого языка (гейты)

1. **Пакет языка** — `translates/<code>.md` + глоссарий. Без него `translate_local` работает
   generic-промптом и печатает NOTE: это допустимо для пилота, но **не для батча**.
2. **Пилот** — 50–100 строк разных типов (диалог, нарратив, UI, меню). Смотрим: обращение,
   род, SFX, типографика, имена. Правим пакет и промпт. Порог приёмки пилота фиксируем числом.
3. **Батч** — весь корпус языка через `translate_local` (resumable, по записи).
4. **Механика** — `npm run qa` → чиним ошибки, пока не станет 0 по «жёстким» правилам.
5. **Судья** — LLM-судья помечает сомнительные строки (не переводит), человек разбирает.
6. **Выборка** — человеческое ревью N строк; приёмка или возврат в п. 2–3.
7. **Сборка и проверка в игре** — `po2dat`, деплой, E2E-сценарий языка.

Стадии 1–3 — машинные и дешёвые; 4–6 — то, что отличает «переведено» от «качественно».

## Порядок языков

Порядок — `config/language-priority.json` (наш собственный файл; копия приоритетов, не импорт).
Источник `en` — `po/template.pot`.

Волны (по фактическому состоянию на 2026-11-22):

- **Волна 1 — `ru`**: 44,4 % (17 888 / 40 256). Доводим до 100 % — это эталон качества,
  на нём калибруются промпт, судья и пороги.
- **Волна 2 — `de`, `pl`**: по 26,8 %. Уже начаты, пакеты есть (DRAFT) → доводим до 100 %.
- **Волна 3 — `zh`, `es`, `pt`**: 0 % + 4 строки. Пакетов нет; пишем пакет → пилот → батч.
- **Волна 4 — `ja`, `fr`, `ko`, `it`**: то же, после волны 3.

Почему не «сначала все по 10 %»: качество одного языка проверяется целиком (пилот → судья →
выборка), а десять недоделанных языков нельзя ни принять, ни отгрузить.

## Что уже есть и чего не хватает

Есть: `potgen`, `po2dat`, `translate_local` (батч), `qa` (Rust, 2.6–3.7× быстрее), `review_queue`,
`translates` (core + ru/de/pl), паритетные тесты, проверка версии игры.

Не хватает (задачи):

- **Пакеты 7 языков** — `tasks/2026-11-21-translates-language-packs.md`;
- **LLM-судья качества** — помечает, не переводит: `tasks/2026-11-22-llm-judge.md`;
- **Протокол пилота** — фиксированные метрики и порог: `tasks/2026-11-22-language-pilot-protocol.md`;
- **Контекст для переводчика** (сцена/ассет/соседи) — `tasks/2026-11-21-pot-context-for-translators.md`;
- **Очередь ручного ревью мусора POT** — `tasks/2026-11-21-pot-noise-cleanup.md`.

## Приёмка языка (definition of done)

- [ ] Пакет языка заполнен и не DRAFT
- [ ] Пилот пройден, порог зафиксирован числом, промпт/пакет поправлены
- [ ] Покрытие 100 % по переводимым строкам (skip-строки и технические — исключены явно)
- [ ] `npm run qa`: 0 ошибок по жёстким правилам, предупреждения разобраны
- [ ] Судья прогнан, флаги разобраны человеком
- [ ] Выборка человека принята
- [ ] `po2dat` собран, E2E-сценарий языка пройден в игре

## Атомарность

Проект самодостаточен: приоритеты, пакеты языков, глоссарии и метрики живут **в этом
репозитории**. TSSR используется только как источник идей (например, генерируемый артефакт
статистики), но не как зависимость: никаких импортов, копий кода и общих файлов. Изменение
приоритетов «там» не меняет ничего «здесь» — при необходимости обновляем свой конфиг руками
и фиксируем дату источника.
