# [2026-11-21] Разметить подозрительные записи POT для ручного ревью (без удаления)

Статус: READY

## Задача от пользователя

«там не всё так просто, это может быть вовсе не мусор, потому что это киберпанк и это вполне
может быть художественным замыслом. поэтому есть предложение перепроверить и чтобы не рисковать
я бы оставил как есть. или как-то пометил для ручного ревью и потом разобрался по паттернам…
там стиль киберпанк и очень сложно что-то от чего-то отличить. только исключительно ручным
ревью. или же как-то бота локального попросить, но за ним всё равно нужно будет ревью, слишком
большие риски выкинуть что-то реально нужное.»

## Цель

Дать человеку **рабочую очередь** подозрительных строк, не трогая сам POT и не удаляя ничего
автоматически. На выходе — воспроизводимый отчёт, по которому можно быстро пройтись руками и
принять решение по каждой строке.

## Ключевое ограничение (почему именно так)

В этой игре «мусорное» имя и художественная строка неразличимы по признаку:
`Femboy_Dicksize_003` рядом с `Drink your COCKtail, Skank.` — обе выглядят «странно»,
но вторая — реплика персонажа. Любой автофильтр выкинет что-то живое. Поэтому:

- **ничего не удаляем и не фильтруем** из POT;
- **никаких правок `po/*.po`**;
- автоматика только **сортирует и подписывает** (почему запись попала в подозрительные),
  решение принимает человек.

## Контекст (замер 2026-11-21)

- POT: 33 271 запись. `isAssetName` матчит 3 045 msgid, `isGarbageFragment` — 1 545,
  объединение 4 297 (пересечение 293). Почти все с контекстом `ui`, 4 — со спикером.
- `potgen.mts` уже умеет классифицировать такие строки (`triageReason`), но результат идёт
  только в счётчик: в POT ничего не пишется (это и сохраняет паритет).
- В `.dat` эти строки и так не попадают (пустой `msgstr` + нет `rich`), то есть на игру
  они не влияют — влияют только на очередь переводчика.

## Что сделать

1. Добавить команду `npm run pot:review` — генератор отчёта (никаких правок POT):
   - `tmp/pot-review.jsonl` — по строке на запись: `{msgid, reason, kind, context, speaker,
length, hasRich}`;
   - `tmp/pot-review.md` — сводка по классам + первые N примеров для быстрого глаза.
2. Классы подозрительности — **не «мусор», а «на что посмотреть»**: `asset-like`,
   `binary-like`, `no-letters`, `looks-like-path`, `single-token`. Класс — подсказка,
   не приговор.
3. Опционально: локальная LLM как **предварительный сортировщик** (proposes order, not decisions).
   Требования: офлайн, без сети, результат помечается «машинная догадка», человек подтверждает.
4. Ревью руками: пройтись по отчёту, для подтверждённых «не переводить» — ставить
   `#, skip` в `po/template.pot` (флаг, не удаление) отдельным коммитом, порциями.
5. Зафиксировать в `MAP.md` скилла: почему автоматическое удаление запрещено.

## Приёмка

- [ ] `npm run pot:review` создаёт оба файла и печатает сводку по классам
- [ ] `po/template.pot` не изменён (побайтово), `po/*.po` не тронуты
- [ ] В отчёте каждая запись имеет причину попадания и контекст (kind/speaker)
- [ ] Ручное ревью одной порции (например 100 записей) выполнено, решения записаны
- [ ] Если LLM-сортировка используется — в отчёте явно видно, что это догадка машины
- [ ] `npm run verify` зелёный

## Вне рамок

- Удаление записей из POT.
- Автоматическое проставление `#, skip` без человека.
- Правка эвристик `isAssetName`/`isGarbageFragment` (см. `pot-coverage-gaps`).
