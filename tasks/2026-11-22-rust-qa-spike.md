# [2026-11-22] QA на Rust: измерить масштабирование (проценты, не секунды)

Статус: DONE (спайк закрыт; включение Rust в `npm run qa` — отдельная задача, `package.json`
вне зоны этой работы)

## Задача от пользователя

«у нас будут и другие игры для работы, и если это будет новелла, там количество данных и времени
круто вырастет, а у нас есть возможность сделать замер в процентном отношении когда проект
маленький, чем потом нагружать железо на большом проекте… поэтому может всё же попробуем Rust…
дело не в секундах, а в процентах».

## Цель

Получить **измеримый коэффициент** TS → Rust на задаче QA (чтение PO/DAT, проверки, отчёт)
и решить по цифре, а не по вкусу. Сейчас данных мало (7 МБ), поэтому мерим **пропускную
способность (МБ/с)** и **масштабирование** на синтетике ×10 и ×100 — чтобы понять, что будет
на крупной новелле, не дожидаясь её.

## Контекст (замер 2026-11-22)

- QA на один язык: **310 мс**, из них **57 мс** — старт Node; входы 3.1 МБ `po` + 2.2 МБ `template.pot`
  - 1.7 МБ `patch_<lang>.dat`.
- Чистый парсинг PO в TS: **57 МБ/с** (31.5 МБ, 409 220 записей за 551 мс).
- Экстраполяция TS: ×10 → ~1.5 с, ×100 → ~15 с. Rust ожидаемо 5–10× быстрее на скане.
- QA — 6 правил: покрытие, баланс тегов, латиница, копия оригинала, пустой диалог, дубли.
  Правила — семантика, поэтому миграция означает **замену** TS-реализации (TS остаётся эталоном
  и оракулом), а не второй параллельный набор правил.

## Что сделать

1. Каркас `tools/rust-qa/` (новый крейт, без тяжёлых зависимостей): чтение `po/template.pot`,
   `po/<lang>.po`, `runtime/patch_<lang>.dat`; разбор через те же контракты, что у TS.
2. Реализовать 6 правил и вывод находок в JSON (формат — как у TS `qa_translate`, чтобы
   сравнение было машинным).
3. **Паритет:** на текущих данных набор находок (level, rule, text) должен совпасть с TS
   **побайтово** (как в порте QA: 1 069 строк ru, 2 834 de).
4. **Замер масштабирования:** прогнать оба на 1× (текущее), 10× и 100× (синтетика генерируется
   скриптом в `tmp/`, без внешних данных). Записать МБ/с и абсолютное время.
5. HTML-отчёт: решить, делать ли его на Rust или оставить в TS (рендер — не узкое место;
   KISS: если Rust отдаёт JSON, TS рисует HTML).
6. `docs/qa-scaling.md`: методика, таблица «объём → TS → Rust → коэффициент», вердикт.

## Журнал 2026-11-22 (спайк выполнен)

### Что сделано

- `tools/rust-qa/` — крейт `rust-qa` (бинарь + библиотека): свой PO-парсер, загрузка
  JSONL `.dat`, 6 правил, вывод JSON (сводка + находки) и JSONL. Единственная зависимость —

  коэффициент и **побайтовый гейт** отчёта TS ↔ Rust на каждой точке.
- `docs/qa-scaling.md` — методика, таблица, решение, условия пересмотра.
- Тесты Rust: 10 (парсер PO) + 17 (правила, `.dat`, сводка, отчёт) — `cargo test` зелёный,
  `clippy -D warnings` и `fmt --check` чисто.

### Паритет

- `ru`: 17 888 / 40 256, errors 725, warnings 959, находок 1 684 — побайтово равен TS.
- `de`: 10 778 / 40 256, errors 729, warnings 0, находок 729 — побайтово равен TS.
- Синтетика: 10× — 19 210 находок, 100× — 200 920; отчёты совпадают побайтово

### Масштабирование (два прогона на точку)

| Объём | Вход, МБ | TS, мс (1/2)    | Rust, мс (1/2) | × (1/2)     | TS, МБ/с | Rust, МБ/с |
| ----- | -------- | --------------- | -------------- | ----------- | -------- | ---------- |
| 1×    | 7.0      | 328 / 298       | 89 / 86        | 3.68 / 3.48 | 23.5     | 81.9       |
| 10×   | 67.7     | 2 168 / 2 164   | 771 / 798      | 2.81 / 2.71 | 31.3     | 84.9       |
| 100×  | 695.4    | 24 193 / 23 660 | 9 198 / 9 044  | 2.63 / 2.62 | 29.4     | 76.9       |

### Решения

- **Мигрируем вычислительное ядро QA на Rust**, TS остаётся эталоном-оракулом. Аргументы:
  2.6–3.7× на всех объёмах (порог ≥ 2×), а на 100× TS вообще падает по heap по умолчанию
  (> ~4 ГБ), Rust работает без флагов.
- **HTML остаётся в TS**: Rust отдаёт JSON, рендер — доли процента времени и второй
  источник истины для оформления не нужен (KISS/DRY).
- Внедрение (`npm run qa` → Rust + HTML в TS, паритет в `test:qa`, Rust-джоб CI) — в
  отдельной задаче: `package.json` в этой работе менять запрещено.

### Гочи (проверено)

- Node на 100× (4 млн записей) падает с `FATAL ERROR: Ineffective mark-compacts near heap
limit` на дефолтном heap; для замера TS запускается с
  `NODE_OPTIONS=--max-old-space-size=8192` (флаг бенчмарка `--ts-heap-mb`). Rust на том же
  входе работает без настройки — это часть результата, а не хитрость замера.
- `cargo` в git-bash не в PATH: нужен `export PATH="$HOME/.cargo/bin:$PATH"` (или запуск из
  PowerShell, где rustup прописан).
- `String.prototype.localeCompare` (сортировка папок) может отличаться от кодового порядка
  только на смешанном регистре; на реальных ключах (`ui`, `dlg`, `raw`, …) порядок совпал —
  зафиксировано в комментарии `rules.rs::dir_cmp`.
