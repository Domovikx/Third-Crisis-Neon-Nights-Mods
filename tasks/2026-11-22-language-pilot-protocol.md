# [2026-11-22] Протокол пилота языка: метрики и порог приёмки

Статус: READY

## Задача от пользователя

«надо подумать что и как мы делаем, сделать план… пользователи ожидают качественный перевод».

## Цель

Зафиксировать **числом**, что значит «пилот прошёл»: сколько строк, какие типы, какие метрики,
какой порог. Без этого каждый язык будет приниматься «на глаз», и качество поплывёт.

## Контекст

- План и стадии — `docs/translation-plan.md` (стадия 2 — пилот).
- Пакеты языков: `translates/core.md` + `<code>.md` (сейчас есть `ru`, `de`, `pl`; остальные 7 —
  задача `translates-language-packs`).
- Механика — `npm run qa`; смысловые флаги — судья (`tasks/2026-11-22-llm-judge.md`).
- Текущее покрытие: ru 44,4 %, de/pl 26,8 %, остальные ~0.

## Что сделать

1. Состав пилота: 50–100 строк, стратифицированно — диалог (2+ спикера), нарратив, UI/меню,
   реплики с `<color>`/rich, короткие междометия, длинные строки (>200 символов), строки
   с именами/терминами.
2. Метрики пилота:
   - механика: 0 ошибок по жёстким правилам `qa`;
   - смысл: доля принятых строк по судье (порог задать числом);
   - терминология: все термины из глоссария применены (сверка списком);
   - род/обращение: 0 ошибок класса «сломан род» на выборке.
3. Порог: «пилот принят, если … %». Зафиксировать после первого прогона на `ru` как эталоне.
4. Шаблон отчёта пилота (markdown) — чтобы по каждому языку оставался след: что было, что
   поправили в пакете, какие термины добавили.
5. Прогнать пилот на `ru` (первый язык) и записать результат как эталон.

## Приёмка

- [ ] Протокол описан в `docs/translation-plan.md` (стадия 2) с числами
- [ ] Пилот на `ru` проведён; отчёт лежит в `tmp/` (данные игры в git не кладём)
- [ ] Порог приёмки зафиксирован числом и обоснован замером
- [ ] Правки, сделанные по итогам пилота, внесены в `translates/ru.md`
- [ ] Те же метрики применимы к `de`/`pl` без изменений

- Правка самих правил языка «на вкус» без замера.
