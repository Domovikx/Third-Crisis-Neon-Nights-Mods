# [2026-11-21] Извлечь студийные голоса игры (референсы для Vox)

Статус: READY

## Задача от пользователя

«нужно также извлечь оригинальные голоса для озвучек это вообще отдельный пласт работы.»

## Цель

Получить из установленной игры **оригинальные студийные реплики** как отдельные аудиофайлы,
привязанные к персонажу и (по возможности) к строке. Это сырьё для клонирования голоса в VoxCPM2:
нам нужны чистые референсы ≥10 с на персонажа, а не «озвучка ради озвучки».

## Контекст (проверено 2026-11-21)

- `AudioClip` в игре есть: `sharedassets*` и анимационные бандлы, формат `.fsb` (FMOD sample bank).
- В текущем дампе большинство клипов помечены **`extract_failed`** — дампер их не декодирует
  (он делает raw-скан, а не разбор аудио). Значит нужен отдельный путь декодирования.
- `AudioSource` в сценах ссылается на клипы через `m_audioClip` и играет через AudioMixer-группу;
  прямой связи «строка текста ↔ клип» в дампе нет.
- Рантайм уже умеет ловить появление строки на экране — это потенциальный способ сопоставления
  в живой игре (лог «строка → имя клипа»).

## Исследовательские вопросы

- Чем декодировать FSB: `UnityPy` (`AudioClip.samples`), `vgmstream`, `fsbext`, ffmpeg — что
  реально берёт FSB5 из Unity 2022 и сохраняет WAV без потерь.
- Где лежат именно **голосовые** клипы, а не SFX/музыка: по каким бандлам/`sharedassets`,
  по каким именам.
- Как сопоставить клип с персонажем: по имени клипа, по сцене/FSM, по `AudioSource`, или только
  по живому логу.
- Хватает ли длительности: студийные реплики короткие (5–15 с), а Vox нужен референс ≥10 с —
  склеивать реплики одного персонажа или искать длинные.
- Лицензионная/этическая сторона: файлы игры не распространяем, используем только локально как
  референсы. Зафиксировать это в доке.

## Что сделать

1. Ресёрч инструментов (веб + локальная проверка на 2–3 клипах).
2. Пробное извлечение: один банк → WAV, проверить слышимость/частоту/каналы.
3. Массовое извлечение в `tmp/voices/` (в git не кладём), с manifest-файлом JSONL:
   `{clip, bundle, path_id, duration, samplerate, channels, guessed_speaker}`.
4. Сопоставление с персонажами: черновая таблица «персонаж → N клипов → суммарная длительность».
5. Отобрать по 1–2 референса на персонажа (≥10 с, чистые), сложить в отдельную папку
   для `voice_design`/`voice_batch`.

## Приёмка

- [ ] Выбран и обоснован декодер (сравнение ≥2 вариантов, вердикт с плюсами/минусами)
- [ ] Извлечено не менее одного банка целиком; WAV открываются, длительность/частота совпадают
- [ ] Manifest JSONL сгенерирован и валиден (одна строка — один клип)
- [ ] Есть таблица «персонаж → сколько клипов и сколько секунд»; видно, кому референса не хватает
- [ ] Скрипт извлечения воспроизводим (повторный запуск не ломает результат, resumable)
- [ ] Артефакты не попали в git (`tmp/`), в задаче записан путь и объём

## Важное уточнение 2026-11-22: аудио — Vorbis, не PCM

У **всех** 7 715 `AudioClip` в дампе `m_CompressionFormat: 1`, то есть **Vorbis** (не PCM).
Значит нужен не «распаковать контейнер», а **декодировать Vorbis внутри FSB5** — а у FMOD там
свой вариант заголовков, обычный Ogg-Vorbis-декодер его не берёт.

Что есть под это:

- **Rust:** `fsbex` (FSB5, умеет Vorbis), `fmod_bank_decoder` (PCM8/16/float нативно + Vorbis),
  `fmod` 0.10.2 (старый, ~3 года без апдейтов).
- **C#:** `Fmod5Sharp` (managed, FSB5).
- **Python:** `python-fsb5` (HearthSim).
- **TS:** зрелого FSB5+Vorbis нет; свой Vorbis — недели работы и высокий риск.

**Предложение:** это тот самый случай, где Rust заслужен, а не «для портфолио»: TS физически
не тянет FSB5+Vorbis, а задача продуктовая (референсы для клонирования голоса). Порядок:
спайк на одном банке (декодировать 1 клип, послушать), затем массовое извлечение.

Ограничение то же: файлы игры не распространяем, только локальные референсы.
