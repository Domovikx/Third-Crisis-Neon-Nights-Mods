# [2026-11-21] Определить судьбу python-острова `dump-assets` (UnityPy)

Статус: READY

## Задача от пользователя

Часть общей задачи: «максимально запускаем миграцию на ts mts вместо питона» — при этом
в `AGENTS.md` зафиксировано, что Python допустим только там, где физически не обойтись.

## Цель

Зафиксировать решение по единственному оставшемуся Python-модулю и не потерять его работоспособность
при переезде: дампер Unity-ассетов должен продолжать работать из нового репозитория, а его тесты —
жить в CI.

## Контекст

- `dump_assets.py` (1334 строки) + `dump_sqlite*.py` — читает `.assets` и `.bundle` игры через
  `UnityPy` (Python-библиотека разбора Unity-сериализации).
- TS-эквивалента нет; писать свой парсер Unity = месяцы и высокий риск.
- Выход дампера — JSONL в `tmp/dump/` (~660 MB), от него зависят `potgen`/`find_source`.
- `dump_assets.test.py` (368 строк) требует `UnityPy`.

## Что сделать

1. Ресёрч (обязательно, с вебом):
   - есть ли на 2026 год жизнеспособные JS/TS-библиотеки разбора Unity assets (искать по
     «unity assets parser typescript/node», «AssetStudio alternative javascript»);
   - можно ли вызывать UnityPy из TS через отдельный процесс (уже так и есть) и что это стоит по
     скорости/сложности;
   - что даёт `.bundle` (LZ4HC) разбор — есть ли готовые реализации вне Python.
2. Сравнить ≥2 варианта:
   - (A) оставить Python-остров, зафиксировать контракт (CLI + формат JSONL), держать тесты в CI;
   - (B) портировать дампер на TS (или через WASM);
   - (C) вызывать внешний .NET/AssetStudio-подобный инструмент.
3. Выбрать и обосновать; при выборе (A) — описать, как остров изолирован: отдельный job в CI,
   `ruff` только по его папке, версия `UnityPy` зафиксирована в `requirements.txt`.
4. Проверить, что дампер запускается из нового репозитория и находит игру через
   `scripts/game_dir.mts` (или через явный `--game`), а не «рядом с репо».

## Приёмка

- [ ] В `docs/migration.md` записано решение с плюсами/минусами и условиями пересмотра
- [ ] `dump_assets.py` находит игру из нового расположения репозитория и пишет дамп в `tmp/dump/`
- [ ] CI-джоб `py-island` зелёный (ruff по папке + тесты дампера)

- [ ] В `AGENTS.md` явно сказано: это единственный Python-остров и почему
