# [2026-11-21] Решить, откуда `prefill` берёт корпус переводов

Статус: READY

## Задача от пользователя

Следствие порта: «`prefill` без корпуса почти пуст… нужно решение владельца отдельной задачей».

## Цель

Определить источник готовых переводов для предзаполнения пустых `msgstr`, иначе инструмент
честно повторяет Python, но не приносит пользы.

## Контекст (проверено 2026-11-21)

- Python-версия брала корпус из `translations/` (YAML-дерево). В новом репозитории этого дерева
  нет и не будет — оно удалено ещё в старом репо.
- Для паритета порт прогнан на корпусе, вытащенном из git-истории старой репы
  (`27eb46b^`, 1 176 файлов, 32 947 записей) — это разовая операция, не рабочий источник.
- Без `--corpus` все строки POT уходят в `missing`, существующие переводы сохраняются:
  то есть инструмент не портит данные, просто ничего не заполняет.
- `prefill` не идемпотентен по статистике: второй прогон даёт `exact 18 610 / fuzzy 0` вместо
  `18 596 / 14` (уже записанный `msgstr` считается подтверждённым, файл при этом тот же).

## Варианты (сравнить и выбрать)

- **A. Корпус = сами `po/<lang>.po`.** Плюс: всегда актуален, ничего не надо поддерживать.
  Минус: если строка есть в целевом PO, она уже заполнена — предзаполнять нечего; польза только
  в переносе между языками.
- **B. Корпус = другие языки** (например, `en`-оригинал + уже переведённые `ru` для `de`).
  Плюс: работает для новых языков. Минус: качество зависит от исходного языка; нужен явный
  приоритет «чей перевод брать».
- **C. Легаси-инструмент.** Плюс: ноль работы. Минус: мёртвый код в репозитории.
- **D. Удалить** и оставить только `translate_local` (перевод моделью) + `po_update`.

## Что сделать

1. Проверить цифрами: сколько строк реально можно предзаполнить вариантом B (для `de`, `pl`,
   и для пустых языков) — это и есть мера пользы.
2. Сравнить варианты по критериям: польза, риск испортить перевод, поддержка.
3. Выбрать; реализовать или удалить инструмент.
