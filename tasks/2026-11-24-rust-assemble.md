# [2026-11-24] Сборка дампа на Rust: максимальный профит как задел на масштабирование

Статус: DONE (параллельная сборка по ассетам — следующий шаг, см. «Дальше»)

## Задача от пользователя

«дело не только в этом это также проект портфолио и тут важно показать максимальный
профит даже если это будет запускаться раз в году… а если я потом захочу масштабировать
наработки то у меня уже будет высоко-эффективное решение которое нужно просто
копипастить и адаптировать.»

То есть правило «≥10 % на реальной нагрузке» остаётся, но частота запуска перестаёт
быть ограничителем: важна демонстрация и переиспользуемость решения.

## Что сделано

Семантика сборки дампа (rd1 → `summaries.jsonl` + `<asset>.jsonl` + `index.md`)
перенесена с TypeScript на Rust и стала рабочим путём:

- `tools/rust-l10n/src/rd1read.rs` — потоковый читатель rd1 (530 МБ) на своём
  парсере: без serde, ключи сравниваются срезами, base64 — своей таблицей;
- `tools/rust-l10n/src/typetree.rs` — разбор type tree Unity и чтение объекта
  (включая причуды эталона: перекрёстные массивы `short`/`ushort`, выравнивания);
- `tools/rust-l10n/src/assemble.rs` — отбор полей, PlayMaker-диалоги, FSM-строки,
  `global_strings`, `settings_keys`, счётчики обрезки, `index.md`;
- `tools/rust-l10n/src/dotnet_scan.rs` — скан `.NET`-кучи `#US` (settings + UI),
  сверен с эталоном на реальном `Assembly-CSharp.dll` (789 строк, совпадение по
  количеству и хэшу содержимого);
- `tools/rust-l10n/src/dumpjson.rs` — писатель JSONL в формате Python `json.dumps`
  (разделители `", "`/`": "`, `repr` плавающих);
- CLI: `rust-l10n dump_assemble <rd1> <out> [--json] [--parse-only] [--*-limit N]`;
- `dump_assets.mts`: флаг `--assembler ts|rust` (по умолчанию Rust, при отсутствии
  бинаря — честное падение на TS-эталон с сообщением);
- тест `scripts/assemble_parity.test.mts` (`npm run test:assemble`) — побайтовое
  сравнение каталогов TS и Rust.

## Замеры (полный корпус: 169 ассетов, 578 474 объекта)

| шаг                                 | время            |
| ----------------------------------- | ---------------- |
| сборка TS (эталон)                  | 11,6 с           |
| сборка Rust                         | 6,5 с (**1,8×**) |
| полный дамп (rust-декодер + сборка) | 60,1 → 53,6 с    |

Паритет: 149/149 файлов побайтово. Профиль сборки: разбор rd1 — 3,2 с
(последовательный), сборка+запись — 3,3 с.

## Пойманные грабли (с тестами)

- **Плавающие на ничьих.** Rust `{}` округляет вверх, Python `repr` — к чётной
  цифре: расходились 11 файлов из 149 (`0.6244583129882812` против `…13`).
  Решение: минимальная точность, при которой `{:.*e}` читается обратно в тот же
  `f64` (форматирование Rust округляет корректно). Тест — `dumpjson::tests`.
- `settings_keys` — массив `[{key, display}]`, `color_parser_list` — объект.
- `path_id` — 64-битное целое без кавычек (в rd1 хранится строкой).
