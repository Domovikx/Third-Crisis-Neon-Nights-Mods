# Протокол работы с задачей

Коротко: **сначала факт, потом действие.** Никаких «по памяти» и «как принято».

## 1. Разобраться в текущем состоянии

До первой правки:

- прочитать `AGENTS.md` и `docs/migration.md` репозитория;
- прочитать сам файл задачи целиком (все секции, включая «Вне рамок»);
- найти смежный код: `grep` по модулю, который трогаешь, и по его вызовам;
- для портов — прочитать **Python-оригинал** (он лежит рядом как референс), а не угадывать
  поведение по названию функции.

Факты в журнал задачи пиши с привязкой `файл:строка` и датой проверки.

## 2. Ресёрч вместо гадания

Если решение неочевидно (как лучше разложить модуль, какая библиотека, как ведёт себя формат) —
сравни **минимум два варианта**, зафиксируй плюсы/минусы и почему исключил. Веб-поиск разрешён
и приветствуется: официальные доки → первоисточники → статьи. Факт из веба — ссылкой и датой;
непроверяемое — `[УТОЧНИТЬ]`.

## 3. Паритет важнее красоты

При порте Python → TS:

1. переносим **поведение**, включая странности и порядок операций;
2. пишем тесты на те же случаи, что в `*.test.py`;
3. **прогоняем оба** на реальных данных репозитория и сравниваем выход
   (`.dat`, `.pot`, `.po`) байт-в-байт, нормализуя `CRLF`→`LF`;
4. только после зелёного паритета удаляем `.py` из нового дерева.

Если паритет невозможен — это повод остановиться и описать причину в задаче, а не «ну и ладно».

## 4. Приёмка — наблюдаемыми фактами

- «файл существует», «команда печатает X», «тест зелёный», «вывод совпал с Python»;
- не «работает аккуратно», «стало чище», «удобнее».

## 5. Сдача

- журнал решения дописан в файл задачи (что сделано, что выяснилось, что осталось);
- статус `DONE`;
- коммит — только если человек явно разрешил.
