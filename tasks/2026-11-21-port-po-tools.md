## Цель

Обслуживание PO-файлов (перенос переводов в новый POT, предзаполнение, поиск источника строки)
работает на TS, без Python. Это ежедневные операции при апдейте игры, поэтому они важнее
разовых скриптов.

## Контекст

- `po_update.py` (151 строка) — перенос `msgstr` в новый `template.pot` по ключам, точный
  перенос / ретаргет / новые пустые записи. Опирается на `po_file.py` (уже портирован).
- `prefill_po.py` (221) — предзаполнение пустых `msgstr` (в т.ч. авто-триаж ассетов и мусора через
  `text_filters`).
- `find_source.py` (62) — поиск источника строки по дампу; импортирует `potgen`.
- Все три пишут PO. Запись обязана быть **атомарной** (`.part` → rename): обрыв процесса не должен
  обнулять файл перевода.

## Журнал

### Что сделано (2026-11-21)

- Портированы все три инструмента, поведение 1:1 (включая странности — см. готчи ниже).
- `writeAtomic` **не дублировался**: взят готовый из `potgen.mts` (тот же `.part` → rename,
  тот же откат `.part` при исключении). `po2dat.mts` исторически несёт свой — не трогал,
  это вне зоны; при следующей правке стоит свести к одному.
- Чтение PO нормализует `CRLF`/`CR` → `LF` (Python `read_text` = universal newlines): иначе
  в шапку `po/*.po` (EOL = CRLF) попадал бы `\r`, и паритет ломался.
- `find_source.mts` использует `inventory.scanDump()` (тот же порядок, что POT-сборка) —
  Python-оригинал звал `potgen.scan_dump()`, который импортировал удалённый `potgen.py`.

### Решения ресёрча

- **Общий atomic-write**: вариант «свой в каждом модуле» отклонён (DRY: уже есть рабочий),
  вариант «новый общий модуль» отклонён (YAGNI: `potgen.mts` уже экспортирует `writeAtomic`,
  а правка `potgen.mts` вне зоны задачи).
- **`prefill` и YAML**: `prefill_po.py` берёт переводы из `translations/` (YAML), а не из дампа —
  в дампе переводов нет вовсе. Порт читает тот же YAML-корпус. Полный YAML не тянем: корпус
  состоит из плоских списков, значения — в двойных кавычках на одной строке, эскейпы только
  `\\`, `\"`, `\n` (проверено сканом 1176 файлов). Реализован мини-парсер подмножества
  (`readYamlEntries`), pyyaml-зависимости нет.
- **Пути**: Python жёстко считал `PATCH_DIR` от `__file__`; в новой репе это работает, но для
  паритета нужен прогон на копии `po/` в `tmp/`, поэтому добавлены флаги `--po-dir`, `--corpus`,
  `--dump`. Это надстройка CLI, дефолтное поведение не изменилось.
- **`find_source` нужен**: без него провенанс недоступен совсем (POT не пишет `#:`, а
  `review_queue`/`stable_index` умерли). Цена — скан дампа 319 МБ (~3 с TS).

### Готчи (кандидаты в `MAP.md`)

- **`prefill` не идемпотентен по статистике**: повторный прогон на уже перезаписанном PO
  считает fuzzy-записи `exact` (msgstr уже есть, флаг `fuzzy` остаётся). Файл при этом
  байт-в-байт тот же. Второй прогон Python в паритете дал 18 610/33 271 и fuzzy 0 — если
  сравнивать «два прогона разных реализаций», всегда брать свежую копию `po/`.
- **Исчезнувший ключ с живым текстом в POT выпадает, а не остаётся legacy**
  (`po_update.py`: `if old["msgid"] in pot_by_text: continue`). Спасение делает только ретаргет,
  и только когда ни один одноимённый ключ не переведён. Это поведение 1:1, не «баг порта».
- **Заголовок `po_update` = первый блок до пустой строки**. В PO без пустой строки (или вовсе
  без шапки) в «шапку» уходит весь файл, и записи дублируются после него. Оставлено 1:1.
- **YAML-корпус — легаси-вход**: в новой репе `translations/` нет, поэтому `prefill` без
  `--corpus` только сохраняет переводы и печатает отчёт (все POT-строки → `missing`).
  Реальный корпус поднимается из git-истории старой репы, копией в `tmp/`, не в репу.
- **Мини-парсер YAML — только подмножество корпуса** (списки, значения в кавычках на одной
  строке). Блочные скаляры (`|`, `>`) и многострочные кавычки не поддержаны: в корпусе их нет.
  Если корпус пересоберут pyyaml'ом с другим стилем — паритет проверить заново.
- **Мини-эталон дампа**: `find_source.mts` по умолчанию смотрит `tmp/dump` репозитория, а дамп
  лежит в папке игры (репо вынесен из неё) → в реальной работе нужен `--dump <…/tmp/dump>`.
- **`--first` и `--dump`**: в Python любой аргумент с `--` отбрасывался, поэтому `--dump` там
  не существует; в TS это новый флаг, значение после него съедается (а не становится текстом).
- **`prefill --lang` не переписывает шапку**: `ruHeaderLines` жёстко пишет `Language: ru`
  и «Russian translation…» (в Python языка не было вовсе — только ru). Для не-ru прогона
  шапка будет врать; запускать `prefill` с `--lang` только для отладки/паритета.

### Открытые вопросы

- **Нужен ли `prefill` в новом мире и с каким корпусом?** Сейчас он честно повторяет Python,
  но без YAML-корпуса его польза = «сохранить переводы + отчёт». Варианты (не выбирал, это
  дизайн): (а) корпус = существующий `po/<lang>.po` (тогда fuzzy/auto-normalized работают
  на живом файле, но семантика отличается от Python); (б) корпус = переводы из других языков;
  (в) оставить как легаси-инструмент для истории. Нужно решение владельца отдельной задачей.
- **`po2dat` gated-порядок** (`tasks/2026-11-21-po2dat-gated-order.md`) остаётся скрытым,
  пока `prefill` не запускают на корпусе с `auto-normalized`.
- **Свести atomic-write к одному хелперу** (`potgen.writeAtomic` + `po2dat.writeDat`) —
  правка вне зоны, кандидат в задачу.
