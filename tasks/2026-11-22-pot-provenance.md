# [2026-11-22] Провенанс строк: откуда строка пришла — и отбор по нему

Статус: READY

## Задача от пользователя

«в этом проекте не получится использовать какие-то фильтры, потому что даже символы в строчке
можно расценивать как художественный замысел… тут кракозябры могут быть и не шумом, а
художественным замыслом, но это не исключает обратного… сложность максимальная».

## Цель

Перестать решать «текст или мусор» по внешнему виду строки. Вместо этого **записывать
происхождение** каждой строки (откуда она взялась) и отбирать по нему — объективному признаку,
который машина знает точно, а человек подтверждает один раз на класс.

## Контекст (замер 2026-11-22)

- Дампер больше не режет текст: `raw_strings` и `#US` без лимитов, обрезки считаются и печатаются.
- POT из нового дампа: **143 872** записи против 40 256, из них ~147 похожи на предложения,
  ~100 688 — обрывки бинарных блобов (`DO\``, `DOa`, `DOi`), ~23 960 — «сырые оболочки» уже
  существующих строк.
- Значит узкое место — слой отбора (`inventory` + `potgen`), а не дампер.
- Отбор по внешнему виду уже доказал несостоятельность: фильтр `dot+upper` режет 737 строк прозы,
  при этом пропускает `!+5=DHISSSSSSSSSSQOJC;1'`.

## Что сделать (только измерение, без смены политики)

1. **Провенанс в инвентаре.** Каждая строка-кандидат получает метку источника:
   - `dialog` — структура диалогов ANToolkit;
   - `bundle` — PlayMaker `line_X`;
   - `field:<ИмяПоля>` — типизированные поля (в бандлах есть type tree);
   - `settings` — `settings_keys[].display`;
   - `us` — куча `#US` из DLL;
   - `raw:<TypeName>` — raw-скан объекта (Texture2D, AudioClip, MonoBehaviour, TextAsset, …);
   - `global` — глобальные строки.
2. **Записать провенанс в POT** комментарием `#. src: <метка>` (рядом с `rich_text`).
   Формат POT меняется осознанно: это и есть источник для политики и для ревью.
3. **Отчёт распределения — главный артефакт**: сколько записей POT по каждому `src`, сколько из них
   попало в POT сейчас, сколько выглядит прозой (мягкий тест), примеры по каждому классу.
   Это покажет, что мы реально отбираем, а что нет.
4. **Никакой смены политики в этом шаге.** Ничего не исключать, не удалять, не менять дефолты.
   Только метки + отчёт с числами.
5. Реализации: оба пути (Rust — рабочий, TS — эталон) с побайтовым паритетом POT.

## Приёмка

- [ ] `#. src:` есть у каждой записи POT; значения — из фиксированного списка
- [ ] Отчёт `docs/pot-provenance.md`: таблица `src → записей → в POT → похоже на прозу → примеры`
- [ ] Паритет TS ↔ Rust побайтовый (POT совпадает)
- [ ] POT-контракт (`npm run pot:check`) не сломан; тесты зелёные
- [ ] Ни одна запись не удалена и не исключена — только помечена
- [ ] На основе отчёта предложена политика (отдельной задачей, с числами)

## Вне рамок

- Изменение того, что попадает в POT (это следующий шаг, после отчёта).
- Ревью «кракозябр» руками (очередь ревью — отдельно).
