# [2026-11-24] Гейт rich-разметки: нет `rich_text` без `rich_translation`

Статус: DOING (расследование и фикс — саб; гейт по этой спецификации)

## Задача от пользователя

«если есть `rich_text` и нет `rich_translation`, то это пропущенный перевод с
тегами и рендер в UI покажет `msgstr` вместо ожидаемого `rich_translation`…
надо это как-то тестами закрывать… самое простое в конце сравнить количество
тегов».

## Контракт

- `rich_text` = `msgid` (оригинал) + теги;
- `rich_translation` = `msgstr` (перевод) + **те же** теги;
- в PO `rich_translation` не хранится — это производная сборки (`po2dat`);
- если `rich_translation` нет, UI молча показывает `msgstr` без оформления.

## Что проверять (два уровня)

### 1. Главный гейт: `.dat` против POT (ловит потерю на сборке)

```text
для каждого языка <lang>:
  A = { ключи POT : есть '#. rich_text:' и строка переводится
                   (нет '#, skip' и нет 'no-translate') }
  B = { ключи .dat : есть размеченный перевод }
  assert A ⊆ B   # каждая ожидаемая строка получила rich_translation
  assert B ⊆ A   # нет размеченных строк, которых нет в POT
```

Сравнение — **по ключу** (`msgctxt \u0000 msgid`), не по глобальному счётчику:
иначе легальные `#, skip` дают ложное падение.

Быстро: оба входа — локальные файлы, без модели и без игры (`.dat` собирается
`po2dat` из `po/*.po`, POT — из `po/template.pot`).

### 2. Дешёвый счётчик в PO (когда/если `rich_translation` начнёт храниться)

```text
count('^#. rich_text:') == count('^#. rich_translation:')
```

Две строки, годится как «сигнальная лампочка» в CI и как быстрый ручной чек.

## Реализация

- Фикстура: `po/template.pot` (или мини-POT из `test_data/pot-golden-small.pot`)
  - маленькая PO с 5–10 строками (часть с тегами, часть без, одна `#, skip`).
- Тест: `node --test` на фикстуре; для реальных данных — opt-in как у остальных
  тяжёлых гейтов (пропуск, если `.dat` не собран).
- Вход в `npm run verify` после того, как фикс подтверждён (иначе красный гейт
  заблокирует остальные правки).
- Разрешение одного вопроса: где именно в `po2dat`/рантайме живёт производство
  `rich_translation` и как оно читается из `.dat` — это часть расследования саба.

## Приёмка

- На фикстуре тест краснеет, если убрать одну `rich_translation`, и зеленеет на
  полном наборе.
- На реальных данных: `A == B` по каждому из 10 языков (или явный список
  остатка с причинами).
- Тест не требует GPU и игры; время — доли секунды.
