# [2026-11-23] Теги «перевод не нужен» в POT + ловля обрывков msgid

Статус: DOING (сделано и проверено; ждут решения владельца — риск правила `short-token` и правила под `w? |b`/`wK Ax`)

## Задача от пользователя

«добавить якорь — не переводить: то, что будет с таким якорем, далее в po попадать не должно,
это сэкономит ресурсы. НО как и кем такую фильтрацию сделать? … такое наверное переводить не надо
[`raw:Transform` `w? |b`, `raw:MonoBehaviour` `wK Ax`]. А вот тут наверное явные баги:
`rich_text: <i>< Like this, hmmm…? … like <b>you</b> request them. >` / `msgid "you request them. >"`.
давай начнём с выявления багов в pot и расстановки тегов на — перевод не нужен».

## Цель

1. **Пометить в POT** записи, которые не надо переводить (`#, skip`), чтобы они **не попадали
   в `po/*.po`** и не тратили ни ревью, ни GPU.
2. **Найти и показать баги POT**, в первую очередь обрывки `msgid` (когда полный текст лежит
   в `rich_text`, а ключ — его хвост).

## Контекст (2026-11-23)

- POT: 33 448 записей, у каждой `#. src:`; политика отбора — `config/pot-src-policy.json`.
- Подтверждённый дефект данных: `#. rich_text: <i>< Like this, … request them. >` при
  `msgid "you request them. >"` — ключ это хвост фразы. Источник — сам дамп (`text` в диалоге
  обрезан, `rich_text` полный). Переводить такой ключ бессмысленно.
- Примеры не-текста от владельца: `msgid "w? |b"` (`raw:Transform`), `msgid "wK Ax"`
  (`raw:MonoBehaviour`).
- Позиция владельца: **фильтры по внешнему виду не решают** (кракозябры могут быть замыслом),
  но и «всё переводить» — трата ресурсов. Решение: **метка + причина + человек подтверждает
  правило один раз**, ничего не удаляется.

## Что сделать

### 1. Инвариант «обрывок»

Добавить в `scripts/pot_invariants.mts` проверку: если у записи есть `rich_text`, то
`strip_tags(rich_text)` и `msgid` должны совпадать (или `msgid` — осмысленная часть).
Расхождение → `rich-fragment` (`warn` на первом шаге, чтобы увидеть масштаб: сколько таких).
Приложить число и 20 примеров.

### 2. Теги «не переводить»

- Политика: `config/pot-skip-policy.json` — **правила по провенансу**, не по вкусу:
  ```json
  {
    "rules": [
      { "id": "no-letters", "src": "raw:*", "when": "noLetters" },
      { "id": "short-token", "src": "raw:*", "when": "shortToken" },
      { "id": "fragment", "src": "*", "when": "fragment" }
    ]
  }
  ```
  `noLetters` — нет ни одной буквы; `shortToken` — нет пробелов и ≤ 12 символов;
  `fragment` — `msgid` есть хвост `rich_text` (см. п.1).
- `potgen` ставит `#, skip` и `#. skip: <id>` рядом с записью. **Запись остаётся в POT**
  (прозрачность; ничего не удаляется).
- `po_update`: для записей с `#, skip` **не создаёт пустых строк в PO** (экономия), а если
  перевод уже есть — сохраняет и помечает.
- `translate_local`: пропускает `#, skip` (в отчёте — отдельный счётчик).
- `qa`: исключает skip из ошибок покрытия (иначе «пустой диалог» на каждой).
- Отчёт для владельца: `tmp/pot-skip-review.md` — по каждому правилу: сколько, примеры (20),
  чтобы можно было подтвердить правило или выключить его в политике.

### 3. Паритет и тесты

- TS ↔ Rust побайтово (POT и отчёт).
- Тесты: каждое правило на фикстуре; `po_update` не создаёт строки для skip; `translate_local`
  не отправляет skip в модель (фейковый сервер); контракт принимает `#, skip`.
