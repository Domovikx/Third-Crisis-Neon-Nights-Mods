# [2026-11-22] Портировать упаковку релиза с PowerShell на TypeScript

Статус: READY

## Задача от пользователя

Решение о стеке (2026-11-22): на проекте TS и Rust равнозначны, Python запрещён, PowerShell
не развиваем. Аудит (`docs/language-audit.md`) оставил `package_release.ps1` единственным
скриптом вне стека.

## Цель

Упаковка релиза (архив мода + раскладка + манифест версии) делается на `.mts`, без PowerShell.

## Контекст

- `package_release.ps1` собирает релизный архив из готовых артефактов (`runtime/*.dat`, DLL,
  шрифты) и проверяет их наличие (`Need-File`).
- Комментарии внутри уже обновлены на `npm run build` / `npm run po2dat`, логика — нет.
- Профит от Rust здесь отсутствует: это I/O (чтение/запись файлов, архивация), язык не влияет.
- `.7z`-упаковка в этом репозитории пока не автоматизирована — решить, нужен ли внешний архиватор
  или достаточно `zip`/каталога.

## Что сделать

1. Прочитать `package_release.ps1` и выписать контракт: что входит в релиз, что проверяется,
   как формируется имя/версия.
2. Решить формат: архив `.7z` (внешний 7-Zip) против `.zip` (Node-совместимо без зависимостей).
3. Реализовать `scripts/package_release.mts`:
   - проверка артефактов с понятными ошибками;
   - сборка архива;
   - печать сводки (что вошло, размер, контрольная сумма).
4. Тесты: раскладка и проверки — на фейковой файловой структуре в `tmp/`; реальная архивация —
   интеграционно, гейтится наличием артефактов.
5. Удалить `package_release.ps1`, обновить `README`/`docs`.

## Приёмка

- [ ] `npm run release` собирает архив из готовых артефактов
- [ ] Отсутствие обязательного файла — понятная ошибка и ненулевой код
- [ ] В архиве ровно те файлы, что перечислены в контракте (сверка списком)
- [ ] Контрольная сумма и размер печатаются
- [ ] `package_release.ps1` удалён; PowerShell в репозитории не осталось
- [ ] `npm run verify` зелёный
