# solid-review — сторож принципов (только чтение)

Аудит изменений на SOLID/DRY/KISS + смежные best practices. Вызывается
напрямую или как саб-агент (`Task`). **Ничего не меняет вообще.**

## Железные запреты

- Запрещены: `Edit`, `Write`, любые `bash`-команды с записью
  (перенаправления, `sed -i`, `git checkout/commit/add`, создание файлов).
- Разрешены только читающие: `Read`, `Grep`, `Glob`, `bash` для чтения
  (`git diff`, `git status`, `git log`, `cat`-подобный осмотр через `Read`).
- Исключение: временные файлы запрещены тоже. Вообще никаких записей.
- Нарушил — отчёт недействителен, так и напиши.

## Когда запускать

- Рекомендуется как проверка перед коммитом: висящий diff → solid-review →
  чинить найденное → коммит. Дешевле, чем вычищать после.
- Также по явному запросу на конкретных путях (см. Вход).
- Не запускать без скоупа и не гонять по расписанию/на весь репозиторий.

## Вход

- Скоуп по умолчанию — ТОЛЬКО git-диффы: висящие изменения в дереве
  (`git status --short` + `git diff HEAD`). Untracked-файлы (`??`) — по явным
  путям из `git status` (в `git diff` их нет, подхватывать руками).
- Коммиты, стеши, чужие ветки, весь репозиторий целиком — НЕ смотрим вообще.
- Вне диффов — только по явному запросу/требованию с конкретными путями
  («посмотри файл X», «проверь скилл Y»). Без путей — отказываться и
  просить скоуп, не расширять молча.
- Языки репо: Python 3.11+ скрипты, C# под старый csc (фактически C# 5:
  без интерполяции, `?.`, expression-bodied), Unity-мод (рантайм в игре).

## Оси анализа (только эти)

- SOLID: SRP, OCP, LSP, ISP, DIP.
- DRY: дубли знаний/логики/конфигов (включая «скоро станет дублем»).
- KISS/YAGNI: сложность без выгоды; код/фичи «на вырост» без потребителя;
  мёртвый код, абстракции впрок.
- Best practices — только с опорой: разрешены `websearch`/`webfetch`
  для подтверждения (версия практики, источник). Без источника — мнение,
  так и помечать.

## Калибровка под репо (что считать риском)

- Горячие пути Unity (`Update`, `OnPreRender`, `LateUpdate`, покадровые
  сканы): аллокации, рефлексия, `Find*` в кадре — высокий риск.
- C#5: предложения синтаксиса новее — инвалидны, не предлагать.
- PO/DAT-пайплайн: правки, ломающие roundtrip `po` или формат `.dat`, —
  критично. Проверять тестами из соседних скиллов, не на глаз.
- YAGNI-порог: мёртвый код с ценой содержания (горячие пути, рост сборки,
  ложные следы в логах) — High. Спекулятивная общность без потребителя
  («на вырост», слоты под 12 языков при одном RU) — High, только если
  усложняет горячий путь или вводит в заблуждение; иначе молча пропустить.
- Порог шума: миноры (стиль, нейминг вкусовщины, `Medium` и ниже) —
  НЕ репортить. Считать молча, в отчёт не включать.

## Формат находки (строго, одна находка = один блок)

```text
FINDING <N> [Critical|High]
Где: файл:строка (или диапазон)
Что не так: одно-два предложения, фактами.
Почему плохо: какой принцип нарушен и как именно + что будет, если игнорить
  (конкретный риск: краш/фриз/потеря переводов/молчаливая порча данных).
Критичность: Critical — ломает/сломает прод или данные; High — риск явно
  выше среднего (перфодеградация, хрупкость, расползание дублей).
Варианты решения:
  A) <что сделать> — почему лучше + какому принципу/практике соответствует.
  B) <альтернатива> — когда предпочтительнее A.
```

- Порядок: сначала Critical, потом High.
- Без находок ≥ High: вердикт одной строкой «Critical/High не найдено»
  - что смотрено (файлы, diff-stat). Миноры не перечислять.
- Предлагаемый код — только текстом в отчёте (скетч, не правка).

## Вызов как саб-агента

```text
Task(subagent_type="general"): "Следуй .opencode/skills/solid-review/SKILL.md.
Скоуп: <пути или 'висящий diff'>. Выведи отчёт этим же сообщением."
```

Саб-агент наследует запреты: любые следы записи = провал задачи.

## После отчёта

- Ничего не чинить, не коммитить, не предлагать «давай поправлю».
- Чинить — отдельная задача по явной команде пользователя.
