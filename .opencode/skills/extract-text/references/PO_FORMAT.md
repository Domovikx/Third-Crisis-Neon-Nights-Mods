# Формат PO/POT: источники и правила оформления

Опорная база для этого скилла: как устроен файл PO, что означают строки
комментариев и какие вещи нельзя «изобретать заново». Всё, что делает наш
парсер (`po_file.mts`) и генератор (`potgen.mts`), должно следовать этому.

## Источники (первоисточники и читаемые объяснения)

- **Спецификация gettext, глава «PO Files»** — texinfo в самом репозитории:
  `gettext-tools/doc/gettext.texi`, раздел про комментарии. Читать прежде
  всего, если поведение инструментов кажется странным.
  - https://www.gnu.org/software/gettext/manual/html_node/PO-Files.html
  - мануал целиком (поиск по `white-space separated`):
    https://www.gnu.org/software/gettext/manual/gettext.html
  - PDF: https://www.gnu.org/software/gettext/manual/gettext.pdf
  - зеркало репозитория: https://github.com/autotools-mirror/gettext
- **translate-toolkit, описание формата PO** (легче читается, с примерами):
  https://docs.translatehouse.org/projects/translate-toolkit/en/latest/formats/po.html
- **Babel, каталог сообщений и флаги**:
  https://babel.pocoo.org/en/latest/messages/catalog.html

Если сеть недоступна — истина всё равно проверяема локально: `msgfmt`,
`msgattrib`, `msgmerge` из пакета gettext и наш `po_file.mts` ведут себя
одинаково (например, флаги — список через запятую).

## Виды строк (каждый знак — свой смысл)

| префикс | что это                                              | пример                                  |
| ------- | ---------------------------------------------------- | --------------------------------------- |
| `#`     | комментарий переводчика (не трогается инструментами) | `# здесь шёпот`                         |
| `#.`    | извлечённый комментарий: пишет генератор             | `#. src: raw:MonoBehaviour`             |
| `#:`    | ссылка на источник                                   | `#: translations/a.yaml`                |
| `#,`    | флаги: машинные пометки, список через запятую        | `#, fuzzy, legacy, skip`                |
| `#      | `                                                    | предыдущий msgid/msgctxt (после правки) | `#\| msgid "Old"` |

Запятая в `#,` — не украшение: это и маркер типа строки, и разделитель
списка флагов. Поэтому `#, fuzzy, skip` — две пометки, а не одна строка
с текстом. Точка (`#.`) уже занята извлечёнными комментариями, двоеточие
(`#:`) — ссылками, поэтому «своя» пунктуация тут не вводится.

Неизвестные флаги инструменты обязаны сохранять: наш парсер хранит их как
строки и не отбрасывает (`po_file.mts`, разбор `#,`).

## Что мы пишем в POT

- `#. src: <метка>` — провенанс записи (`docs/pot-provenance.md`, инвариант 14
  контракта `docs/pot-contract.md`).
- `#. rich_text: <разметка>` — исходный TMP-текст для рантайма (цвет/курсив).
- `#, skip` + `#. skip: <id>` — «перевод не нужен» (`docs/pot-skip.md`).
- `#, legacy` — строка пришла из старого PO и уже не встречается в игре.
- `#, fuzzy` — перевод требует проверки (стандартная семантика gettext:
  инструменты не используют такой перевод без подтверждения).

## Правила, которые нельзя нарушать

1. **Порядок записей** — сортировка по `(msgid, msgctxt)` (сравнение code
   points, как в Python). Иначе диффы неустойчивы.
2. **Экранирование** — `"` и `\` экранируются, перевод строки — `\n` внутри
   строки. Реальные переводы строк внутри `msgstr` (не `\n`) — дефект: так
   ломаются заголовки (`48` битых заголовков было найдено в `es/ja/pt/zh`).
3. **Многострочные значения** — склейка подряд идущих строк в кавычках;
   `msgid ""` + `msgstr ""` в начале файла — заголовок, а не пустая запись.
4. **Один ключ = одна пара `(msgid, msgctxt)`** во всём файле. Дубли в
   пределах одного PO — исключение Ren'Py/движка, у нас запрещены.
5. **Запись атомарная** (`<файл>.part` → rename): обрыв процесса не должен
   обнулять PO.
6. **`msgctxt` — часть ключа.** Перенос перевода при смене контекста —
   отдельное решение (`retarget`), а не «совпал текст — значит тот же».

## Проверки в репозитории

- `npm run pot:check` — инварианты `po/template.pot` (включая `#, skip`
  против политики и `rich-fragment`);
- `npm test` — парсер/рендер PO, round-trip, паритет Rust ↔ TS;
- `npm run po:check` — целостность PO (обнуление, усечение, `.part`).

## Наши машинные комментарии (что читает конвейер)

- `#. src: <метка>` — провенанс записи (POT).
- `#. rich_text: <оригинальная разметка>` — текст с TMP-тегами; po2dat кладёт его в поле `r`.
- `# rich_translation: <разметка перевода>` — **перевод разметки**; po2dat кладёт в `rt`, а
  рантайм выбирает `rich_translation` ПЕРВЫМ (`rich_translation > translation > rich_text > text`).
  Старое имя `# rich:` остаётся алиасом; если есть оба, побеждает `rich_translation:`.
  Нужен там, где автоматическая сборка невозможна (теги внутри фразы, ~385 строк): без него
  перевод покажется без цвета/курсива.
- `#. skip: <правило>` + `#, skip` — «перевод не нужен» (`docs/pot-skip.md`).
- `#. repaired: <обрезанный текст>` — ключ восстановлен по `rich_text` (дефект данных AN).

`#` — комментарий переводчика (сюда пишутся `rich_translation:`), `#.` — извлечённый
комментарий. Менять их местами нельзя: парсер кладёт их в разные списки.
