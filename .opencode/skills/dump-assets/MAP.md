# MAP — dump-assets (факты и грабли)

Python-эталон (UnityPy 1.25.0) + TS-порт стадий 0–2. Проверено на
установленной игре и дампе 2026-11-21/22.

## Готчи (Python-эталон)

- ⚠️ **После переезда репозитория дампер искал игру не там** → `GAME_DIR` брался
  как `PATCH_DIR.parent` (работало, пока репо лежал внутри папки игры) →
  проверено: в новом дереве `DATA_DIR` указывал на `C:\Users\Domo\workspace\…`
  → добавлен `TCNN_GAME_DIR` (`resolve_game_dir()`), pytest 26/26 зелёные,
  тест `test_resolve_game_dir_env_override` → всегда запускать с
  `TCNN_GAME_DIR="<Steam>/steamapps/common/Third Crisis Neon Nights"`.

- ⚠️ **В дампе 19,4 % объектов не читаются** → `read_failed` у MonoBehaviour
  (87 790 объектов), `extract_failed` у AudioClip/Texture2D → проверено:
  92 652 объекта, 196 864 raw-строки → для таких объектов есть только
  `raw_strings` (≤100), поэтому часть диалогов/FSM-текста в POT не попадает
  (`tasks/2026-11-21-pot-coverage-gaps.md`); для голосов `AudioClip` вообще
  не декодируется (см. `tasks/2026-11-21-extract-studio-voices.md`).

- ⚠️ **`raw_strings` обрезаны до 100 на объект** → `entry["raw_strings"] =
all_texts[:100]` (dump_assets.py, строка ~900) → проверено чтением кода;
  документация раньше говорила «top 20» — исправлено → если строка диалога
  «глубже» в raw, её в дампе нет; сначала проверять дамп, потом фильтры.

- ⚠️ **`global_strings` в summaries никто не читает** → `scan_global_strings`
  пишет до 500 UI-кандидатов на ассет (296 summary-строк, 132 806 строк
  всего), но `inventory.mts` читает только `settings_keys` → проверено
  замером 2026-11-21: из них 8 921 «человекочитаемая» по мягкому фильтру и
  1 089 строгих предложений не в POT, но в основном это обрывки бинарного
  скана → включать только с фильтром и ревью, не «влить всё».

- ⚠️ **`path_id` бывает отрицательным и 64-битным** → в дампе 6 485 уникальных
  значений за 2^53, в том числе отрицательные (`-5271052525308704166`) →
  проверено тестом инвентаря → python-сторона пишет их как int без потерь,
  TS-сторона обязана читать BigInt (см. MAP `extract-text`).

- ⚠️ **Дамп большой, но не «навсегда»** → 319 МБ, 477 872 строки, 131 чанк +
  summaries; полный прогон TS-инвентаря ≈ 5 с, прежний Python ≈ 31 с →
  проверено 2026-11-21 → дамп не коммитить (`tmp/` в `.gitignore`),
  регенерировать после апдейта игры.

- ⚠️ **Тесты дампера требуют установленную игру** → `dump_assets.test.py`
  грузит `level0`/`resources.assets` из `DATA_DIR` → проверено: без env
  используется старый фолбэк, с `TCNN_GAME_DIR` — 26/26 → в CI без игры
  гонять только чистые функции (raw-скан, JSON-парсинг), не «файловые»
  тесты.

## TS-порт (стадии 0–2): факты и грабли

- ✅ **Заголовок SerializedFile — big-endian, содержимое — по флагу** →
  проверено на `level0` байтами: legacy-префикс (metadataSize/fileSize/version/
  dataOffset) и v22-блок (metadataSize/fileSize/dataOffset/unknown) читаются
  BE; `endian`-байт = 0 → остальное LE. Ошибка «прочитать всё reader'ом с
  текущим endian» ломает разбор уже на type count.

- ✅ **`byte_start` в object table относительный** → UnityPy прибавляет
  `header.data_offset`; проверено на синтетике тестом (абсолютное значение
  даёт удвоение dataOffset) и на реальных файлах: SHA-1 сырых байт объектов
  совпал с UnityPy для level0 (5 объектов) и бандла (3 объекта), 2026-11-22.

- ✅ **Контейнер UnityFS — big-endian целиком** (заголовок И blocksInfo:
  count/размеры/offset/имена). Содержимое SerializedFile внутри — уже LE.
  Проверено на 107 бандлах игры.

- ⚠️ **Запись блока в blocksInfo — 10 байт, не 12** → `u32 uncompressedSize +
u32 compressedSize + u16 flags`; проверено: бандл с 65 блоками падал на
  проверке `count*12`, после исправления — паритет.

- ✅ **LZ4HC (флаг 3) на декомпрессии = обычный LZ4 block** → свой декодер
  (`lz4.mts`) на 107 бандлах; ffprobe-подобных внешних тулов не нужно.

- ✅ **LZMA-фолбэк реализован на TS** (`lzma.mts`, raw LZMA1: props + dictSize
  LE + поток) → проверено синтетическим вектором от xz/LZMA1 (2 набора
  lc/lp/pb) и тестом блока UnityFS; у игры LZMA-бандлов нет, это «на всякий».

- ⚠️ **`.resS`/`.resource`/`.config`/`.xml`/`.dat` нельзя пробовать как
  SerializedFile** → `.resS` начинается нулями, legacy-version = 0, и
  детектор «похоже на SerializedFile» даёт ложное срабатывание; UnityPy
  отсекает по расширению (`ImportHelper.parse_file`) → повторяем список и
  требуем версию ≥ 9 в `peekSerializedHeader`; иначе бандл целиком помечался
  «битым» (проверено на `0.3-animation-maxxcustomercg`).

- ✅ **Type tree: `.assets` — ВЫКЛЮЧЕН, бандлы — ВКЛЮЧЕН** → проверено на всех
  141 файлах: `level*`/`sharedassets*`/`resources` — `typeTree=false`,
  все бандлы — `true`. Парсер обязан уметь пропускать blob (v22: узел 32
  байта + string buffer + type dependencies). Для стадии 3 это значит:
  типы в `.assets` придётся описывать вручную, а в бандлах дерево уже есть.

- ⚠️ **Паритет структуры: пробу делает не весь `dump_assets.py`** → полный
  прогон пишет 319 МБ и ходит по всем файлам; харнесс запускает тот же
  UnityPy на выбранном наборе. Entry-список UnityPy наружу не отдаёт, поэтому
  проба подменяет `BundleFile.read_files` и запоминает nodes (monkeypatch
  только для чтения; файлы не меняются).

- ⚠️ **Discovery Python ограничен `level0..15`/`sharedassets0..15`** → в
  установке есть `level16..18` и `sharedassets16..18`, они НЕ попадают в дамп
  (проверено листингом 2026-11-22). TS пока повторяет поведение эталона, чтобы
  паритет набора файлов не разъезжался; расширять — отдельным решением
  (иначе POT может недополучать текст из поздних сцен).

- ⚠️ **`globalgamemanagers.assets` и `globalgamemanagers` имеют одно display-имя**
  → Python дедупит по display и второй файл пропускает; TS повторяет, иначе
  в дампе было бы два «globalgamemanagers».

- ⚠️ **Выравнивание UnityFS**: после заголовка — при `formatVersion >= 7`
  (у игры 8), перед блоками данных — если выставлен флаг `0x200`. Старый/
  новый набор флагов различается по версии движка (2020.3.34 / 2021.3.2 /
  2022.1.1): в новых `0x200` — паддинг, в старых — бит шифрования.

- ✅ **Сырые байты объектов идентичны UnityPy** → SHA-1 первых 12 символов
  совпал для `level0` (path_id 1..5) и бандла `0.2pinup-rosiesspecial`
  (3 объекта), 2026-11-22 → stage 2 закрыта по существу.

- ⚠️ **Node запускает `.mts` через type stripping** → нельзя parameter
  properties (`constructor(private x: …)`), enum'ы и namespace'ы; проверено
  падением `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` → поля класса объявляются
  явно.

- ⚠️ **`path_id` в JSONL — сырое целое, не строка** → Python пишет int без
  потерь, `JSON.parse` в JS округляет >2^53, а `JSON.stringify(BigInt)` падает
  → `inventory.mts` вытаскивает значение регуляркой `"path_id": (-?\d+)`
  (см. `PID_RX`); стадия 3 обязана писать строку JSONL вручную (или
  сериализатором с BigInt), а не через `JSON.stringify` объекта.
