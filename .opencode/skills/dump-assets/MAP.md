## TS-порт (стадии 0–2): факты и грабли

- ✅ **Заголовок SerializedFile — big-endian, содержимое — по флагу** →
  проверено на `level0` байтами: legacy-префикс (metadataSize/fileSize/version/
  dataOffset) и v22-блок (metadataSize/fileSize/dataOffset/unknown) читаются
  BE; `endian`-байт = 0 → остальное LE. Ошибка «прочитать всё reader'ом с
  текущим endian» ломает разбор уже на type count.

- ✅ **`byte_start` в object table относительный** → UnityPy прибавляет
  `header.data_offset`; проверено на синтетике тестом (абсолютное значение
  даёт удвоение dataOffset) и на реальных файлах: SHA-1 сырых байт объектов
  совпал с UnityPy для level0 (5 объектов) и бандла (3 объекта), 2026-11-22.

- ✅ **Контейнер UnityFS — big-endian целиком** (заголовок И blocksInfo:
  count/размеры/offset/имена). Содержимое SerializedFile внутри — уже LE.
  Проверено на 107 бандлах игры.

- ⚠️ **Запись блока в blocksInfo — 10 байт, не 12** → `u32 uncompressedSize +
u32 compressedSize + u16 flags`; проверено: бандл с 65 блоками падал на
  проверке `count*12`, после исправления — паритет.

- ✅ **LZ4HC (флаг 3) на декомпрессии = обычный LZ4 block** → свой декодер
  (`lz4.mts`) на 107 бандлах; ffprobe-подобных внешних тулов не нужно.

- ✅ **LZMA-фолбэк реализован на TS** (`lzma.mts`, raw LZMA1: props + dictSize
  LE + поток) → проверено синтетическим вектором от xz/LZMA1 (2 набора
  lc/lp/pb) и тестом блока UnityFS; у игры LZMA-бандлов нет, это «на всякий».

- ⚠️ **`.resS`/`.resource`/`.config`/`.xml`/`.dat` нельзя пробовать как
  SerializedFile** → `.resS` начинается нулями, legacy-version = 0, и
  детектор «похоже на SerializedFile» даёт ложное срабатывание; UnityPy
  отсекает по расширению (`ImportHelper.parse_file`) → повторяем список и
  требуем версию ≥ 9 в `peekSerializedHeader`; иначе бандл целиком помечался
  «битым» (проверено на `0.3-animation-maxxcustomercg`).

- ✅ **Type tree: `.assets` — ВЫКЛЮЧЕН, бандлы — ВКЛЮЧЕН** → проверено на всех
  141 файлах: `level*`/`sharedassets*`/`resources` — `typeTree=false`,
  все бандлы — `true`. Парсер обязан уметь пропускать blob (v22: узел 32
  байта + string buffer + type dependencies). Для стадии 3 это значит:
  типы в `.assets` придётся описывать вручную, а в бандлах дерево уже есть.

- ⚠️ **Паритет структуры: полный прогон эталона не нужен** → полный
  прогон пишет 319 МБ и ходит по всем файлам; харнесс запускает тот же
  UnityPy на выбранном наборе. Entry-список UnityPy наружу не отдаёт, поэтому
  проба подменяет `BundleFile.read_files` и запоминает nodes (monkeypatch
  только для чтения; файлы не меняются).

- ⚠️ **Discovery Python ограничен `level0..15`/`sharedassets0..15`** → в
  установке есть `level16..18` и `sharedassets16..18`, они НЕ попадают в дамп
  (проверено листингом 2026-11-22). TS пока повторяет поведение эталона, чтобы
  паритет набора файлов не разъезжался; расширять — отдельным решением
  (иначе POT может недополучать текст из поздних сцен).

- ⚠️ **`globalgamemanagers.assets` и `globalgamemanagers` имеют одно display-имя**
  → Python дедупит по display и второй файл пропускает; TS повторяет, иначе
  в дампе было бы два «globalgamemanagers».

- ⚠️ **Выравнивание UnityFS**: после заголовка — при `formatVersion >= 7`
  (у игры 8), перед блоками данных — если выставлен флаг `0x200`. Старый/
  новый набор флагов различается по версии движка (2020.3.34 / 2021.3.2 /
  2022.1.1): в новых `0x200` — паддинг, в старых — бит шифрования.

- ✅ **Сырые байты объектов идентичны UnityPy** → SHA-1 первых 12 символов
  совпал для `level0` (path_id 1..5) и бандла `0.2pinup-rosiesspecial`
  (3 объекта), 2026-11-22 → stage 2 закрыта по существу.

- ⚠️ **Node запускает `.mts` через type stripping** → нельзя parameter
  properties (`constructor(private x: …)`), enum'ы и namespace'ы; проверено
  падением `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` → поля класса объявляются
  явно.

- ⚠️ **`path_id` в JSONL — сырое целое, не строка** → Python пишет int без
  потерь, `JSON.parse` в JS округляет >2^53, а `JSON.stringify(BigInt)` падает
  → `inventory.mts` вытаскивает значение регуляркой `"path_id": (-?\d+)`
  (см. `PID_RX`); стадия 3 обязана писать строку JSONL вручную (или
  сериализатором с BigInt), а не через `JSON.stringify` объекта.

## Стадия 3 (объекты и JSONL): факты и грабли

- ✅ **Type tree в бандлах — ключ ко всей типизированной части** → 107/107
  бандлов `typeTreeEnabled=true`, 34/34 `*.assets` — `false`. Поэтому
  `strings`/`fields`/`fsm_strings` читаются generic-обходом дерева
  (`typetree.mts`) ТОЛЬКО в бандлах; для `.assets` тип объекта неизвестен и
  строка помечается `read_failed` (как у эталона на MonoBehaviour).
  Для POT это не важно: `strings.m_Name` нужен только для бандлов
  (`collectBundle` в `inventory.mts`).

- ⚠️ **Общие строки type tree (старший бит смещения)** → у v22 имя узла может
  быть ссылкой в таблицу «common strings» (`offset | 0x80000000`); без неё
  `type`/`name` не декодируются (46/48 узлов первого бандла — из таблицы) →
  таблица 112 имён завендорена в `typetree.mts` (данные TPK, не код);
  проверено паритетом `fsm_strings`/`strings` на бандлах.

- ⚠️ **Эталон падает на AudioClip/Texture2D/Sprite (`extract_failed`)** →
  `extract_object` перебирает `dir(data)`, а у этих классов есть свойства
  (`samples`, `image`), которые пытаются декодировать ресурс и вызывают
  `PermissionError` на пути-каталоге → строка дампа = только `path_id`+`type`,
  без `raw_strings` → **6 329 объектов** (AudioClip 6 246, Texture2D 79,
  Sprite 4) → POT эталона теряет **1 537** записей, которые TS находит
  (AudioClip 1 495, остальное 42) → это не расхождение разбора: после подмены
  этих 6 329 строк на TS-строки POT совпадает 37 663 = 37 663, 0 диффов
  (проверено 2026-11-22). Записывать «в эталоне crash = норма» в наш код
  нельзя; см. `tasks/2026-11-21-dump-assets-island.md`.

- ⚠️ **`strings`/`fields` для `.assets` не восстановить без базы typetree
  UnityPy** → встроенные классы (GameObject, Sprite, AudioClip, …) эталон
  читает не из файла, а из своей `lzma.tpk` (≈1000 описаний) → 140 404 строки
  с `strings.m_Name` в эталонном дампе TS-дампер не повторяет. На POT не
  влияет (см. выше); полный JSONL-паритет стадии 4 потребует либо схем, либо
  вендоринга базы (решение — за владельцем).

- ⚠️ **`ColorParserList` читается шагом 24 байта, а не 16** → эталон
  `_read_entry` возвращает `off2 + 24` (проверено и на синтетике, и на реальном
  `resources`: 5 цветов) → при порте нельзя «исправлять» шаг, иначе список
  перестанет находиться (первый же тест на синтетике ловит).

- ⚠️ **Raw-скан включает пробел (0x20) в прогон** → `scan_raw_strings` собирает
  байты 32..126 и делает `.strip()`, то есть строка может начаться с пробела →
  проверено на `Camera` level1: `" AX9"` без `.strip()` давало лишний пробел в
  JSONL и расхождение с эталоном.

- ⚠️ **JSON-диалог: `\n` внутри строки превращается в букву `n`** →
  `_extract_json_string` кладёт сам байт после слэша (0x6E), а не перевод
  строки → это поведение эталона, порт его повторяет буквально (иначе текст
  диалогов разъедется).

- ⚠️ **`raw_strings` у эталона — это `all_texts[:100]`, а `dialogues` — все** →
  обрезка только в JSONL-поле, но `parse_playmaker_dialogues` работает по
  `all_texts` (без обрезки) → порядок важен: сначала полный скан, потом срез.

- ⚠️ **`settings_keys` приходят НЕ только из dll** → `scan_settings_keys`
  гоняется по сырым байтам КАЖДОГО файла (в т.ч. бандлов), а не только
  `.assets`; на реальном дампе ключи есть у `resources` (57), `level7` (1) и
  двух DLL (537 + 151), и `set`-строки в POT идут из них.

- ⚠️ **`summaries.jsonl` эталона дописывается (`open(..., "a")`)** → повторный
  прогон в тот же каталог даёт ДУБЛИ строк; TS-дампер перезаписывает файл
  (правильное поведение), и это единственное намеренное расхождение формата.

- ⚠️ **Python-дампер удалён 2026-11-22** (вместе с `requirements.txt` и py-джобом CI).
  Эталон теперь — `rawdump.mts` (TS) и `tests/rust_parity.test.mts`, которые сверяют две
  реализации на реальной игре. Если понадобится старый эталон — берите из git-истории или из
  старого репозитория `NeonTranslator`; в рабочем дереве его нет.

- ⚠️ **Дамп в старом репо устарел** → он снят 2026-09-29, игра обновлена
  2026-11-12: `level10` 15 264 → 6 304 объекта, хэши бандлов другие, появились
  `level16..18` → паритет снимать ТОЛЬКО на свежем прогоне эталона, иначе
  расхождения формата не отличить от расхождений версии игры.

## Готчи двух реализаций (2026-11-22)

- ⚠️ **Граница стоит ~523 МБ.** `rd1` несёт байты типизированных объектов и blob'ы type tree
  (+33 % к исходному объёму). Это цена того, что правила извлечения не дублируются в Rust.
  Проверено: полный прогон, `tmp/raw/`.
- ⚠️ **JSON как транспорт запрещён.** `JSON.parse` превращает `60.0` в `60` и ломает побайтовый
  паритет типизированных полей. Поэтому `rd1` передаёт **сырые байты/блоб**, а не объекты.
- ⚠️ **`--decoder rust` без собранного бинаря — код 2**, а не молчаливый откат на TS. Проверено:
  сообщение об ошибке + инструкция `npm run rust:build`.
- ⚠️ **Горячий участок — печатные строки файлов** (437 млн прогонов): TS вызывает `TextDecoder`
  на каждый прогон, Rust хэширует срез. Отсюда 3× на байтовом уровне; семантику (11 с) Rust
  не ускоряет — там правила, а не байты.
