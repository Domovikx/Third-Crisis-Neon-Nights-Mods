# MAP — translate-qa (факты и грабли)

Офлайн-QA (`scripts/qa_translate.mts`) и очередь ревью
(`scripts/review_queue.mts`). Порт с Python выполнен 2026-11-21; `.py` рядом —
референс до удаления, не править и не звать.

## Готчи

- ⚠️ **QA читает `.dat`, а не только PO** → `loadDat()` открывает
  `runtime/patch_<lang>.dat` → если `.dat` старый, отчёт врёт про покрытие →
  проверено (`loadDat`, сводка ru 18 610/33 271) → сначала
  `npm run po2dat -- <lang>`, потом QA.

- ⚠️ **PO и `.dat` уже расходятся** → 55 строк `.dat` отличаются от `po/ru.po`
  (сборка 2026-11-21), плюс 14 текстов имеют пустой `msgstr` в PO, но непустой
  `x` в `.dat` → проверено сравнением карт (`t` → `x` против `msgid` → `msgstr`)
  → цифры QA считаются по `.dat`; перед релизом пересобрать `.dat`, иначе
  «переведено» и «в игре» — разные числа.

- ⚠️ **Проверка «латиница в RU» — не проверка длины** → условие
  `[...tr].length > 10 && cyrRatio < 0.3` — поиск непереведённой латиницы, а не
  «короткий/длинный перевод» → проверено чтением `check()` → лимиты длины в QA
  не добавлять (правило AGENTS.md). `[...tr].length` (кодовые точки) — паритет с
  Python `len()`, обычный `.length` считал бы UTF-16.

- ⚠️ **Дубли в PO искались в POT — правило было мёртвым** → Python-версия
  складывала `msgstr` из `template.pot`, где он всегда пуст, поэтому
  `duplicate-po` не срабатывал никогда → в TS источник `po/<lang>.po`
  (задумано по описанию правила) → проверено: на `ru.po`/`de.po` дублей нет
  (0 находок), числа паритета не изменились.

- ⚠️ **Copy-through в диалогах — error, но legacy-строки исключены** → флаг
  `sk` (legacy) снимает проверки 2/4/6, `#, no-translate` — все содержательные →
  проверено фикстурой и корпусом (58 errors: 48 tag-imbalance + 10 copy-through)
  → если массово «copy-through», сначала смотреть `sk`/`no-translate`, а не
  править перевод.

- ⚠️ **Дисбаланс тегов сравнивает ИМЕНА тегов, не текст** → `r` и `rt` режутся
  `/<[^>]+>/g`, сравниваются первые слова тегов → в детали отчёта формат списка
  отличается от Python (через запятую без кавычек), число находок и их состав
  совпадают → на формат деталей не опираться, только на `level+rule+text`.

- ⚠️ **`sourcedir_of` на текущем POT всегда `ui`** → POT больше не пишет `#:`
  refs, поэтому группировка «по папкам» выродилась в одну строку `ui` (33 271) →
  проверено (`grep -c '^#: ' po/template.pot` = 0) → не удивляться пустой
  таблице папок; вернётся вместе с refs из `pot-context-for-translators`.

- ⚠️ **`review_queue` без `stable_index` — не сломанная, а другая** → соседи
  берутся по порядку в po-файле (алфавит по тексту), группировка — по спикеру;
  «ассета/сцены» в данных нет → проверено чтением PO (refs = 0) → не пытаться
  восстановить сцены из PO; это отдельная задача про refs в POT.

- ⚠️ **«missing» меньше числа пустых `msgstr`** → если у текста есть хоть один
  заполненный вариант в другом контексте, все его пустые варианты в очередь не
  попадают (так же было в Python) → проверено на `po/ru.po`: 14 675 пустых
  записей, но 14 661 missing (14 пустых строк относятся к 8 текстам с
  заполненным двойником) → не искать баг в счётчике; таково правило «текст уже
  переведён где-то».

- ⚠️ **Триаж видимости (quest/FSM) — не работа QA** → строки
  `TalkToKlaudia - 1_Agree` помечаются массово skip человеком, QA их только
  показывает → проверено описанием процесса в SKILL.md → не «переводить всё
  подряд», чтобы позеленить отчёт.

## Паритет с Python (проверено 2026-11-21)

  языках (1 069 и 2 834 строк).

## Готчи

- ⚠️ **`tag-imbalance` ложно срабатывает на `<font>`.** Симптом: 48 из 58 «ошибок» ru —
  `<color …>,</color>` слева против `<color …>,<font=…>,</font>,</color>` справа.
  Причина: `<font>`/`<material>` сидят в `rt` (перевод) из старых `# rich:`-оверрайдов,
  а генерация POT вырезает их из `rich_text` — рантайм выбирает шрифт сам.
  Проверено: 2026-11-21, после фильтра `^<\/?(?:font|material)\b` ошибок ru стало 11 вместо 58.
  Что делать: не «чинить» перевод, теги шрифта в сравнении вёрстки не участвуют.
- ⚠️ **QA читает `.dat`, а не PO.** Симптом: `de` показывает `0 / 33 271`, хотя в `po/de.po`
  11 156 переводов. Причина: `runtime/patch_de.dat` не собран. Проверено: 2026-11-21.
  Что делать: перед отчётом `npm run po2dat -- <lang>` для всех языков.
- ⚠️ **`.dat` и PO расходятся.** Пересборка словарей 2026-11-21 дала `ru` 18 535 строк,
  `de`/`pl` по 11 088, остальные 2 008 (только rich). Числа «в игре» и «в PO» — разные, пока
  `.dat` не пересобран.
