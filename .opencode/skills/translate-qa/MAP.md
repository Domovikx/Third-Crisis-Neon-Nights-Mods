# MAP — translate-qa (факты и грабли)

Офлайн-QA перевода: **движок правил — Rust** (`tools/rust-qa`), запуск через
`scripts/qa.mts` (сводка + HTML на TS), **золотой отчёт** —
`test_data/qa-golden-<lang>.json` (оракул), очередь ревью —
`scripts/review_queue.mts` (TS).

2026-11-24: TS-движок `scripts/qa_translate.mts` удалён (решение владельца «всё
TS-легаси выпиливаем»). Роль TS-эталона заменил золотой JSON; HTML-рендер
перенесён в `scripts/qa.mts` (решение 2026-11-22: рендер на TS, вычисления на Rust).

## Как устроено

- `scripts/qa.mts` — CLI: `--lang`, `--out`, `--help`. Ищет бинарь в
  `tools/rust-qa/target/release/rust-qa[.exe]`, зовёт его с
  `--root <репо> --lang <l> --json tmp/qa-<l>.json --quiet`, JSON → `Summary` →
  `renderHtml` → HTML. Код 1 при errors, 2 если бинаря нет.
- `tools/rust-qa` — 6 правил, JSON-отчёт (свой PO-парсер из `rust-l10n-core`).
- `test_data/fixture-<lang>/` + `test_data/qa-golden-<lang>.json` — замороженный
  срез корпуса и отчёт-оракул. Пересборка — `test_data/build_golden.mts`.
- `tests/qa_golden.test.mts` — Rust против золота (структура + ПОРЯДОК находок).
- `tests/qa_rules.test.mts` — поведение правил и исключений на фикстурах.
- `scripts/qa_render.test.mts` — HTML-дашборд (`renderHtml`) и `toSummary`.

## Готчи

- ⚠️ **QA читает `.dat`, а не только PO** → `rust-qa` открывает
  `runtime/patch_<lang>.dat` → если `.dat` старый, отчёт врёт про покрытие →
  проверено (`ru` 18 445 записей POT, покрытие считается по `.dat`) → сначала
  `npm run po2dat -- <lang>`, потом QA.

- ⚠️ **PO и `.dat` расходятся** → строки `.dat` отличаются от `po/<lang>.po`
  (сборка 2026-11-21), плюс часть текстов имеет пустой `msgstr` в PO, но непустой
  `x` в `.dat` → проверено сравнением карт → цифры QA считаются по `.dat`; перед
  релизом пересобрать `.dat`, иначе «переведено» и «в игре» — разные числа.

- ⚠️ **Проверка «латиница в RU» — не проверка длины** → условие
  `chars > 10 && cyr_ratio < 0.3` — поиск непереведённой латиницы, а не
  «короткий/длинный перевод» → лимиты длины в QA не добавлять (правило
  AGENTS.md). В Rust `s.chars().count()` — кодовые точки, паритет с Python
  `len()`/TS `[...s].length`.

- ⚠️ **Дубли в PO искались в POT — правило было мёртвым** → Python-версия
  складывала `msgstr` из `template.pot`, где он всегда пуст, поэтому
  `duplicate-po` не срабатывал никогда → сейчас источник `po/<lang>.po`
  (задумано по описанию правила) → на `ru.po`/`de.po` дублей нет (0 находок).

- ⚠️ **Copy-through в диалогах — error, но legacy-строки исключены** → флаг
  `sk` (legacy) снимает проверки 2/4/6, `#, no-translate` и `#, skip` — все
  содержательные → проверено фикстурой и корпусом → если массово
  «copy-through», сначала смотреть `sk`/`no-translate`, а не править перевод.

- ⚠️ **Дисбаланс тегов сравнивает ИМЕНА тегов, не текст** → теги режутся
  `<[^>]+>`, сравниваются первые слова → в детали отчёта список через запятую
  без кавычек (`<b>,</b> vs <b>`), на формат деталей не опираться в правилах,
  только на `level+rule+text` (в тестах деталь зафиксирована как контракт).

- ⚠️ **`tag-imbalance` ложно срабатывает на `<font>`** → `<color …>,</color>`
  слева против `<color …>,<font=…>,</font>,</color>` справа. Причина:
  `<font>`/`<material>` сидят в `rt` из старых `# rich:`-оверрайдов, а генерация
  POT их вырезает — рантайм выбирает шрифт сам. Проверено 2026-11-21 (58 → 11
  ошибок). Что делать: не «чинить» перевод; теги шрифта в сравнении вёрстки не
  участвуют (фильтр `^</?(?:font|material)\b`).

- ⚠️ **`sourcedir_of` на текущем POT всегда `ui`** → POT больше не пишет `#:`
  refs, группировка «по папкам» выродилась в одну строку `ui` → проверено
  (`grep -c '^#: ' po/template.pot` = 0) → не удивляться пустой таблице папок;
  вернётся вместе с refs из `pot-context-for-translators`.

- ⚠️ **`rust-qa` не создаёт каталоги для `--json`** → `std::fs::write` падает,
  если родителя нет → проверено на стенде (`tmp/qa-bench/out/...`) → вызывающий
  код делает `mkdirSync(dirname(out))`; тесты кладут JSON в уже созданный `tmp`.

- ⚠️ **Формат отчёта Rust = `JSON.stringify(report)` побайтово** → проверено
  2026-11-24: файл `--json` совпал с `JSON.stringify(JSON.parse(...))` на обоих
  языках → в золото пишем pretty-JSON (читаемый дифф), а сверяем структуру:
  форматирование контрактом НЕ является, порядок находок — является.

- ⚠️ **Золото нельзя снимать с живого `po/`** → перевод идёт ежедневно, тест
  краснел бы по чужой работе → золото снимается с фикстуры-среза
  (`build_golden.mts`), входы лежат в `test_data/fixture-<lang>/` → фикстура
  содержит все строки, дававшие находки, и сэмпл чистых (шаг 41).

- ⚠️ **`review_queue` без `stable_index` — не сломанная, а другая** → соседи
  берутся по порядку в po-файле (алфавит по тексту), группировка — по спикеру;
  «ассета/сцены» в данных нет → проверено чтением PO (refs = 0) → не пытаться
  восстановить сцены из PO; это отдельная задача про refs в POT.

- ⚠️ **«missing» меньше числа пустых `msgstr`** → если у текста есть хоть один
  заполненный вариант в другом контексте, все его пустые варианты в очередь не
  попадают (так же было в Python) → проверено на `po/ru.po`: пустых записей
  больше, чем missing → не искать баг в счётчике; таково правило «текст уже
  переведён где-то».

- ⚠️ **Триаж видимости (quest/FSM) — не работа QA** → строки
  `TalkToKlaudia - 1_Agree` помечаются массово skip человеком, QA их только
  показывает → не «переводить всё подряд», чтобы позеленить отчёт.

## Замеры (контекст)

- 2026-11-22 (`docs/qa-scaling.md`): Rust быстрее TS-эталона в 2.6–3.7×, на 100×
  TS падал по heap. После удаления TS-эталона стенд
  (`scripts/qa_scaling_bench.mts`) мерит только Rust и проверяет детерминизм
  двух прогонов; столбцы «TS / паритет» из него убраны.
- 2026-11-24, реальный корпус (POT 18 445 записей): `ru` 14 363 заполнено,
  43 error / 136 warning; `de` 7 805, 722 error (678 empty-dialogue, 44
  copy-through). Отчёт `ru` = 34 КБ, `de` = 126 КБ.
